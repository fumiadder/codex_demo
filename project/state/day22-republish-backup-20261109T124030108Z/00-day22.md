### 文生视频工作原理

**文生视频的核心思想**：将一段文字描述，通过AI逐步“翻译”成一段连续、动态的视频。

想象你要拍摄一部**8秒钟的微电影**，剧本是：“一个现代女性在博物馆拿手机拍照，然后不小心摔倒了”。传统拍摄需要演员、场地、摄影机、剪辑师。而AI生成视频则是这样工作的：**文本输入 → 理解剧本 → 搭建场景 → 逐帧绘制 → 连接成片**。

### 各节点作用详解

#### 1. **Checkpoint加载器（简易）**

**作用：加载AI的“大脑”**

- **原理**：这是整个系统的**预训练模型**，包含了AI学习过的所有视觉知识和绘画规则。
- **比喻**：就像聘请一位经验丰富的**导演+摄影师+动画师**团队，他们已经看过数百万部电影和图片，知道如何把文字变成画面。

#### 2. **CLIP文本编码**

**作用：把文字翻译成AI能懂的“视觉密码”**

- **原理**：CLIP将文本和图像映射到同一个语义空间中。
- **比喻**：编剧把剧本拆解成**分镜指令**。
- **工作过程**：
  1. 输入：“现代女性”、“博物馆”、“拍照”、“摔倒”
  2. 输出：一组**768维的数学向量**（数字密码）
  3. 这些向量不是文字，而是**视觉特征的数学描述**

#### 3. **空Latent视频（LTXV）**

**作用：创建视频的“空白画布”**

- **原理**：在**潜空间**中创建一个空的视频容器。
- **比喻**：准备一部**空的电影胶片**，确定了长度和尺寸，但内容全是空白。
- **参数意义**：
  - **宽度768×高度512**：每帧画面的分辨率
  - **长度161帧**：总帧数（161÷18≈8.9秒视频）
  - **批量大小1**：一次生成1个视频

#### 4. **采样算法（SD3）**

**作用：确定AI的“绘画方法论”**

- **原理**：定义了如何从噪声逐步生成清晰图像的具体数学方法。

- **比喻**：决定画家是**从轮廓开始画**，还是**从细节开始画**。

- **SD3的特点**：

  - 稳定性高，生成质量好
  - 支持较少的采样步数（如4步）也能出效果

- 参数：移位

  - 控制生成内容的“创意自由度”

    - **实际有效范围**：0.0 ~ 20.0（超过20通常无实际意义）
    - **常见工作范围**：0.5 ~ 10.0

  - 想象你在教AI画画：

    - **移位=0**：AI严格按你教的方法画，不出格
    - **移位=1.0**：AI会加入一些自己的想法，可能超出预期
    - **移位=8.00**（如图中设置）：AI有**很大的创意发挥空间**

  - 典型分段区间：

    | 移位值         | 范围描述      | 常见用途             |
    | :------------- | :------------ | :------------------- |
    | **0.0 ~ 1.0**  | 保守/精确区   | 产品设计、精确概念图 |
    | **1.0 ~ 3.0**  | 标准/平衡区   | 常规创作、商业项目   |
    | **3.0 ~ 6.0**  | 创意/艺术区   | 艺术创作、概念探索   |
    | **6.0 ~ 10.0** | 高自由/实验区 | 实验艺术、风格探索   |
    | **10.0+**      | 极端随机区    | 纯实验、抽象艺术     |

#### 5. **K采样器**

**作用：执行实际的图像生成过程（核心引擎）**

- **原理**：执行**扩散模型的反向过程**，将随机噪声逐步转化为有意义的图像。

- **比喻**：导演实际指导每一帧的拍摄。

- **工作步骤**：

  1. **初始化**：在潜空间创建161帧的**随机噪声**（像电视雪花）

  2. **去噪过程**（以4步为例）：

     ```
     第1步：AI问“根据剧本，这堆噪声应该是什么？”
            → 减少一些噪声，露出大致轮廓
     
     第2步：AI问“现在更像什么了？”
            → 进一步细化，出现基本形状
     
     第3步：AI问“细节应该是什么？”
            → 添加纹理和细节
     
     第4步：AI问“最终效果如何？”
            → 精修完成，得到清晰图像
     ```

- **采样器名称**：`euler_ancestral`（一种快速收敛的采样方法）

- **调度器**：`beta`（控制噪声减少的节奏）

#### 6. **VAE解码**

**作用：将潜空间表示转换为真实图像**

- **原理**：变分自编码器的解码部分，将压缩表示“解压”成像素图像。
- **比喻**：将**设计稿**加工成**成品照片**。

#### 7. **Video Combine**

**作用：将静态帧序列合成为视频文件**

- **原理**：使用视频编码器将图片序列压缩为标准视频格式。
- **比喻**：将拍好的**照片胶卷**冲洗成**电影放映带**。
- **参数配置**：
  - **帧率18**：每秒播放18帧（基本流畅）
  - **格式H.264 MP4**：最通用的视频格式
  - **CRF 19**：压缩质量参数（23是默认，19更高质量）
  - **像素格式yuv420p**：兼容性最好的色彩编码
- **输出结果**：一个可直接播放的`.mp4`文件

#### 8. **图层工具：清除VRAM**

**作用：清理显卡内存，防止资源耗尽**

- **原理**：释放不再需要的模型和数据，为后续操作腾出空间。
- **比喻**：拍完一场戏后，**清理片场**，准备下一场。
- **两种清理模式**：
  1. **清除缓存**：清理中间计算结果（如已处理的图像数据）
  2. **清除模型**：卸载AI模型本身（约5-7GB）
- **使用场景**：
  - 生成多个视频后防止内存不足
  - 切换不同模型前释放空间
  - 解决程序崩溃问题

  - 识别物体、人物、场景
  - 理解颜色、构图、风格
  - 将视觉信息映射到语义空间

**工作示例**：

#### CLIP视觉编码

**通俗理解**：

评论家开始**详细分析画作**，并写出**分析报告**：

- 这份报告用**专业术语**写成
- 其他节点能看懂这份报告
- 报告是**数字形式**的，不是文字

**实际作用**：

- **输入**：图片 + CLIP视觉模型
- **过程**：提取图片的深层语义特征
- **输出**：768维的**语义向量**（数字密码）

**具体编码过程**：

```
# 假设图片内容：戴面纱的女人
图片像素 → CLIP视觉编码器 → 语义向量

# 向量中的部分数值可能代表：
数值[0:100]:  人物特征（0.8表示“女性”）
数值[100:200]: 服饰特征（0.9表示“面纱”）
数值[200:300]: 风格特征（0.7表示“国画风”）
数值[300:400]: 场景特征（0.6表示“古朴建筑”）
```

**重要特点**：

1. **不是像素复制**：而是提取“本质特征”
2. **可计算的距离**：
   - “戴面纱的女人”和“戴帽子的女人”向量距离近
   - “戴面纱的女人”和“汽车”向量距离远
3. **与文本兼容**：同一个向量空间
   - 文字“女人”也会生成类似向量

**示例对比**：

```
原始图片：1024×768×3 ≈ 235万个像素值
编码后：1×768个数值（压缩了3000倍！）

好处：
1. 节省计算资源
2. 抓住本质，忽略细节噪音
3. 便于与其他条件（文本）融合
```

#### 核心节点介绍

##### 节点一：**`Load Video (Upload)` **——【加载原始视频】

从本地上传一个视频文件，并解析其信息（如帧率、分辨率等），供后续节点使用。

**参数详解：**

| 参数                             | 值            | 含义                                                         |
| :------------------------------- | :------------ | :----------------------------------------------------------- |
| `video`                          | `dance.mp4`   | 你要上传的视频文件名（实际运行时点击“choose video to upload”选择） |
| `force_rate`                     | `30`          | 强制将视频帧率设为 30 fps（即使原视频不是）。有助于统一处理速度。 |
| `custom_width` / `custom_height` | `0`           | 自定义宽高，0 表示不修改原尺寸。若填入数值会缩放视频。       |
| `frame_count_cap`                | `93`          | 最多读取多少帧（防止内存爆炸）。比如只处理前93帧测试。       |
| `skip_first_frames`              | `0`           | 跳过开头几帧（用于跳过黑屏或无脸画面）。                     |
| `select_every_nth`               | `2`           | 每隔 N 帧选一帧处理（例如=2 就是每隔一帧处理，降低计算量）。 |
| `format`                         | `AnimateDiff` | 指定输出格式，这里表示要用于 AnimateDiff 类型模型（非关键，主要是兼容性） |

> 💡 提示：如果你视频很长，建议适当设置 `frame_count_cap` 和 `select_every_nth` 来节省时间和显存。

##### 节点二：**`ReActor - Fast Face Swap` **——【核心换脸节点】

这是真正的“换脸”操作核心！它能识别源视频中的人脸，然后替换成你指定的目标人脸（source_image）。

**参数详解：**

| 参数                                           | 值                      | 含义                                                      |
| :--------------------------------------------- | :---------------------- | :-------------------------------------------------------- |
| `input_image`                                  | ✅ 已勾选                | 输入的原始视频帧（来自上一步 Load Video）                 |
| `source_image`                                 | ✅ 已勾选                | 你的“目标人脸”照片（即你想换上去的脸）                    |
| `face_model`                                   | `inswapper_128.onnx`    | 使用的换脸模型（推荐使用 inswapper 系列，速度快且效果好） |
| `face_boost`                                   | ON                      | 开启增强模式，提高面部细节还原质量                        |
| `swap_model`                                   | `inswapper_128.onnx`    | 换脸模型路径（与 face_model 相同）                        |
| `face_detection`                               | `retinaface_resnet50`   | 人脸检测算法，准确率高，适合复杂背景                      |
| `face_restore_model`                           | `codeformer-v0.1.0.pth` | 修复换脸后可能出现的模糊或失真问题（如皮肤质感）          |
| `face_restore_visibility`                      | `0.50`                  | 修复强度（0～1），越高越清晰但可能过度处理                |
| `codeformer_weight`                            | `0.50`                  | CodeFormer 模型权重，控制修复程度                         |
| `detect_gender_input` / `detect_gender_source` | no                      | 是否根据性别优化检测，一般保持 no 即可                    |
| `input_faces_index`                            | `0`                     | 选择输入视频中第几个脸进行替换（多个脸时用）              |
| `source_faces_index`                           | `0`                     | 选择 source_image 中第几个脸作为模板（多脸图时用）        |
| `console_log_level`                            | `1`                     | 控制日志输出级别，1 是正常提示                            |

> ✅ 关键技巧：
>
> - 如果你想让换脸更自然，建议开启 `face_boost`
> - `face_restore_visibility` 和 `codeformer_weight` 可以调到 `0.7～0.8` 提升画质
> - 若你有多个脸，记得调整 `faces_index`

##### **节点三：**`RIFE VFI` **——【插帧补帧，提升流畅度】**

对处理后的视频帧进行“插帧”（Video Frame Interpolation），把原本每秒30帧变成60帧甚至更高，使动作更顺滑！

**参数详解：**

| 参数                         | 值           | 含义                                                    |
| :--------------------------- | :----------- | :------------------------------------------------------ |
| `frames`                     | ✅ 已勾选     | 输入的是已经换完脸的视频帧序列                          |
| `ckpt_name`                  | `rife47.pth` | 使用的插帧模型文件（rife47 是目前最常用且效果好的版本） |
| `clear_cache_after_n_frames` | `10`         | 每处理10帧清一次缓存，避免内存溢出                      |
| `multiplier`                 | `2`          | 帧数倍增系数，`2` 表示原来30fps → 60fps；`3` → 90fps    |
| `fast_mode`                  | `true`       | 快速模式，牺牲一点点精度换取速度                        |
| `ensemble`                   | `true`       | 启用集成预测（多个模型投票），提升稳定性                |
| `scale_factor`               | `1`          | 缩放因子，1 表示不缩放，保留原分辨率                    |

> 💡 注意：
>
> - 插帧会让视频更流畅，但也增加显卡负担
> - 推荐使用 `rife47` 或 `rife49`，性能和效果平衡最好
> - 设置 `multiplier=2` 是最常见的需求（30→60fps）

##### **节点四：**`Video Combine` **——【合并并导出最终视频】**

把所有处理好的帧（包括换脸+插帧后的结果）重新组合成一个完整的视频文件并保存。

**参数详解：**

| 参数              | 值               | 含义                                                         |
| :---------------- | :--------------- | :----------------------------------------------------------- |
| `frame_rate`      | `30`             | 输出视频的帧率（注意：如果前面用了 RIFE 插帧，应改为 `60` 才匹配） |
| `loop_count`      | `0`              | 循环播放次数，0 表示只播放一次                               |
| `filename_prefix` | `AllInOne01`     | 输出文件名前缀（最终文件名为 AllInOne01.mp4）                |
| `format`          | `video/h264-mp4` | 输出格式，MP4 是通用格式，H.264 是编码方式                   |
| `pix_fmt`         | `yuv420p`        | 颜色格式，兼容性最强，几乎所有设备都能播放                   |
| `crf`             | `19`             | 压缩质量参数（CRF），值越小质量越高（18～23 是推荐范围）     |
| `save_metadata`   | `false`          | 不保存元数据（如创建时间等），减小文件大小                   |
| `trim_to_audio`   | `false`          | 不裁剪到音频长度（适用于无声音视频）                         |
| `pingpong`        | `false`          | 是否来回播放（如动画回放），一般不用                         |
| `save_output`     | `true`           | 是否保存输出文件（必须打开才能看到结果）                     |

> ✅ 实用建议：
>
> - 如果你在 RIFE 中设置了 `multiplier=2`，请在这里把 `frame_rate` 改成 `60`
> - CRF 设为 `19` 是高质量，但文件较大；想压缩可设 `23`
> - 输出路径通常在 ComfyUI 的 `output` 文件夹下

#### 使用建议

1. **显存不足怎么办？**
   - 减少 `frame_count_cap`
   - 增加 `select_every_nth`（如设为 4，只处理每4帧）
   - 关闭 `face_boost` 或降低 `face_restore_visibility`
2. **换脸不自然？**
   - 尝试更换 `face_model`（如 `inswapper_128.onnx` vs `inswapper_128_v2.onnx`）
   - 调整 `face_restore_visibility` 到 0.7～0.8
   - 确保 source_image 是清晰正面照
3. **视频卡顿？**
   - 检查 `frame_rate` 是否与 RIFE 的 `multiplier` 匹配
   - 使用 `fast_mode=true` 在 RIFE 中加速
4. **如何调试？**
   - 先只处理前几帧测试（`frame_count_cap=10`）
   - 分步运行：先跑 Load → ReActor → 查看中间帧是否正常

# 什么是 Codex

这节课，我们先来认识一下 Codex，看看它究竟是什么，以及它能够帮助我们完成哪些事情。

## 一、如何理解 Codex

简单来说，**Codex 就是一名能够自主完成任务的 AI 程序员。**

使用 Codex 时，你不需要一步一步地教它怎么操作，只要把自己想要实现的目标告诉它，它就可以主动编写代码、运行程序，并在出现问题时继续排查和修复。

听到这里，你可能会觉得有些不可思议。没关系，接下来我们一步一步拆开来看。

## 二、为什么 Codex 最近这么火

很多人第一次接触 Codex 时，可能都会产生一个疑问：

> Codex 不就是一个能够编写代码的 ChatGPT 吗？

这个问题非常有代表性，但实际上，Codex 和普通的对话型大模型并不是一回事。

想要理解二者之间的区别，我们需要先了解 AI 发展的两个阶段。

### 第一阶段：语言大模型时代，也就是 LLM 时代

LLM 指的是大语言模型，例如 DeepSeek、豆包和 ChatGPT。

在这个阶段，AI 更像是一位知识丰富、擅长思考，却不能直接替你执行任务的顾问。

你向它提出一个问题，它可以帮你分析原因、提供建议，并告诉你接下来应该先做什么、再做什么。但是，真正执行这些操作的人依然是你。

换一种更直白的说法就是：

> AI 负责思考和指导，你负责动手执行。

它可以给你提供方案，却无法独立把整个任务完成。

### 第二阶段：Agent 时代，也就是智能体时代

进入 Agent 时代以后，AI 的工作方式发生了明显变化。

你只需要向 AI 提出一个明确的目标，它就能够主动分析需求、拆分任务、调用工具、编写代码并运行程序。

整个任务会由 AI 持续向前推进，不再需要你参与每一个操作步骤。

**Codex 正是 Agent 时代的代表性产物，这也是它真正强大的地方。**

## 三、Codex 的核心工作流程

理解了 Agent 的概念以后，我们再来看一下 Codex 具体是怎样完成任务的。

假设你向 AI 提出这样一个需求：

> 帮我制作一个网站。

### 普通语言大模型的处理方式

普通大语言模型通常会按照下面的流程帮助你：

1. 根据需求生成一段代码。
2. 你把代码复制下来，再手动运行。
3. 如果运行过程中出现错误，你需要把报错信息重新发送给它。
4. 它根据报错内容给出修改建议。
5. 你按照建议继续修改并再次运行。

如果问题还没有解决，你就需要不断重复以上步骤。

在这个过程中，每一个环节都离不开你的参与。你需要在 AI 和实际运行环境之间不断传递代码、报错信息和执行结果，相当于充当了一个“传话筒”。

### Codex 的处理方式

Codex 的工作流程则完全不同：

1. 收到你的目标以后，先自主分析需求并拆分任务。
2. 操作终端，编写代码、调整配置并搭建页面。
3. 如果运行过程中出现错误，主动查找原因并进行修复。
4. 完成修复后重新运行程序，继续检查效果并优化。
5. 持续重复执行、检查和修复，直到把产品制作出来。

在整个过程中，你不需要亲自参与每一步操作，只需要告诉 Codex 最终想要实现什么，它就会围绕这个目标持续推进任务。

# 让 Codex 帮你完成第一件事

## 打开界面，先和 Codex 聊起来

进入 Codex 后，你首先会看到一个醒目的对话输入框。

面对这个输入框，应该从哪里开始呢？

根据我的使用经验，不需要一开始就提出复杂的任务，可以先和它进行一次简单的交流。现在的 AI 已经非常智能，所以每当我接触一款全新的 AI 工具时，通常都会先输入这样一句话：

```text
你好，你可以帮我做些什么？
```

这个过程就像认识一位新朋友。先简单打个招呼，了解一下它具备哪些能力，再决定接下来让它帮我们完成什么事情。

## 第一个任务：整理桌面

接下来，我们给 Codex 安排一项比较简单的任务，通过这个过程感受一下它是如何工作的。

你可以向 Codex 输入下面这段指令：

```text
你可以帮我整理一下桌面吗？我希望把不同类型的文件分别放进对应的文件夹，同时将常用的应用程序按照类别摆放在桌面的不同位置。请先对桌面内容进行一次盘点，等我确认整理方案后再开始操作。
```

收到这条指令以后，Codex 并不会马上移动桌面上的文件，而是先进行一次“只查看、不操作”的盘点。

完成盘点后，它会把准备采用的整理方案展示给你。只有得到你的确认，它才会正式开始整理和移动文件。

这样的工作方式非常贴心：先让你了解它准备如何处理，再根据你的决定执行，而不是没有经过确认就直接开始操作。

![image-20260914092125053](assets/c81412bc1520e0d2.png)

## 理解“自动审核”

在 Codex 执行任务的过程中，你可能会注意到界面上出现“自动审核中”这几个字。

那么，“自动审核”究竟是什么意思呢？

Codex 这类 AI 智能体，可以读取、移动、删除和编辑电脑中的文件。它拥有的操作能力越强，相应的风险也会越高。如果操作过程中误删了重要内容，就可能带来不必要的麻烦。

因此，在真正执行任务之前，Codex 会先对本次操作进行评估，判断它是否存在较高风险，以及是否需要提前征求你的同意。

这个判断和评估的过程，就是“自动审核”。

## 审核权限应该怎么选择

在对话框下方，你可以看到三个与审核权限相关的选项：

1. **请求批准**：Codex 执行每一步操作前，都需要先获得你的同意，整个过程由你亲自把关。
2. **替我审批**：一般操作可以直接执行，只有遇到高风险操作时，Codex 才会向你请示。
3. **完全访问权限**：Codex 可以自行处理所有操作，不再频繁打扰你，相当于把电脑的钥匙全部交给了它。

我们可以用皇上和宰相的关系来理解这三种权限。

“请求批准”就像皇上事事亲自过问；“替我审批”则是皇上只负责重要决策，把普通事务交给宰相处理；至于“完全访问权限”，就相当于宰相掌握了全部权力，可以自行决定如何处理。

我个人更建议选择**“替我审批”**。这样既能减少频繁确认带来的麻烦，又可以保留一定的控制权。

当然，我也能理解，很多人在使用一段时间以后，可能会忍不住直接开启“完全访问权限”。毕竟大家都希望操作更省事一些，这也是很正常的。

## 看看 Codex 是如何工作的

完成权限设置以后，Codex 便开始自动执行任务。经过大约 10 分钟的处理，它成功读取了桌面中的文件，并按照要求完成了整理。

<img src="assets/79c79badeeeeef78.png" alt="image-20260914092304018" style="zoom:67%;" />

通过前面的桌面整理案例，我们可以非常直观地看到：Codex 并不是一个只能陪你对话的 AI，而是一名能够实际操作本地文件的智能体助手。

如果换一种形象的说法，它就像一位住在电脑里的数字员工。

日常使用 Codex 时，大多数情况都是这样的：你先向它下达一条指令，接下来的五六分钟甚至十几分钟里，Codex 会在电脑中一步一步地执行任务，并在完成相应操作后向你汇报进度。

执行过程中遇到问题，它会先尝试自己分析并解决。只有确实需要获得操作权限，或者需要你补充相关信息时，它才会主动向你询问。

## 一个使用心态：允许 AI 犯错

最后，我想分享一个非常重要的使用心态：

> 允许 AI 出错，也要允许 AI 自己尝试和折腾。

你可以把 Codex 理解成公司里刚刚入职的一名实习生。实习生在完成任务时，难免会出现一些让你感到无奈甚至抓狂的操作。

但是遇到这种情况，最不应该做的，就是立刻终止它的工作，然后自己接手处理。

先让它尝试，也允许它经历错误，它才能逐渐掌握正确的做事方法。使用 Codex 也是同样的道理：适当给它一些处理问题的空间，使用起来才会越来越顺手。



# 如何选择模型与查看用量

这一节课，我们主要了解两件事情：如何选择模型，以及怎样查看当前的额度用量。

## 一、查看当前用量

查看用量的方法非常简单，只需要按照下面的步骤操作：

1. 点击界面左下角的**“设置”**。
2. 点击**“剩余用量”**。

这里显示的用量，可以简单理解为：你目前还可以让 Codex 帮你完成多少工作。

如果额度已经全部消耗完，Codex 就会暂时停止工作。

例如，当界面显示“5 小时 91%”时，代表在当前 5 小时的使用周期内，你还剩下 91% 的用量；如果显示“一周 97%”，则表示本周的可用额度还剩 97%。

## 二、用量耗尽后怎么办

当 Codex 的可用额度已经耗尽时，可以通过以下两种方式解决：

1. **升级订阅计划**：选择更高级别的订阅套餐，例如 **PRO**。套餐等级越高，相应的用量上限也会越高。
2. **等待额度自动恢复**：如果暂时不想升级套餐，也可以等待当前周期结束。到达额度恢复时间后，用量会自动补满，耐心等待即可。

<img src="assets/410fd6b18fef4722.png" alt="image-20260914092529522" style="zoom:67%;" />

## 三、选择模型

查看完剩余用量以后，接下来我们再了解一下如何选择模型。

首先点击左上角的**“新对话”**，然后查看对话框右下角。在这里，你会看到一个用于切换模型的按钮。

当前显示的是 **“5.5”**，代表现在使用的是 GPT-5.5 模型。随着技术不断发展，未来还可能出现 GPT-6.0、GPT-7.0 等新版本，界面中的模型选项也会随之更新。

点击模型按钮并展开下拉菜单后，你会看到两组设置选项。

### 1. 推理层级

推理层级分为以下四档：

- **低**
- **中**
- **高**
- **超高**

推理层级设置得越高，Codex 对任务的思考就会越深入，同时消耗的用量也会相应增加。

这就像让员工加班工作一样：投入的精力越多，需要消耗的资源自然也就越多。

### 2. 速度选项

速度分为以下两种模式：

- **标准**
- **快速**

选择**“快速”**模式后，Codex 完成任务的速度会有所提升，但相应的用量消耗也会变成原来的 1.5 倍。

因此，速度和用量之间需要做出取舍，具体如何选择，就要看你更加重视哪一个方面。

### 3. 推荐设置

日常使用 Codex 时，怎样设置会更加合适呢？我的建议如下：

- **模型**：选择当前的最新版本。现在可以选择 **“5.6”**，以后出现新版本时再跟随更新。
- **推理层级**：使用默认的**“中等”**即可，没有必要一开始就调整到最高档位。
- **速度**：继续使用**“标准”**模式，可以减少用量消耗，让额度使用得更加持久。

对于大多数日常任务来说，这套默认设置已经完全够用。只有在处理特别复杂的任务时，才需要考虑将推理层级调高。

# 如何使用项目文件夹功能

## 一、什么是“项目”

这一节课，我们来了解一下如何在 Codex 中设置项目。

对于“项目”这个概念，大家不需要理解得过于复杂。简单来说，项目就是你电脑中的一个文件夹。

完成项目设置以后，Codex 会读取这个文件夹里的所有内容，并将这些文件和资料作为完成任务时的工作背景。与此同时，Codex 后续生成的文件也会直接保存在这个项目文件夹中。

## 二、项目文件夹的两种设置方式

设置项目文件夹时，可以从下面两种方式中选择：

1. 创建一个新的空文件夹，从头开始完成项目。
2. 选择电脑中已经存在的文件夹，其中可以包含现有的工作文件和相关资料。

![image-20260914092724175](assets/2c02fc73b6c4a4be.png)

## 三、实战案例：整理一个杂乱的文件夹

接下来，我们通过一个实际案例，看看如何整理一个内容混乱的文件夹。

假设你的电脑中存在这样一个文件夹：里面存放着图片、表格和文档等多种格式的文件，文件类型非常杂乱；文件名也缺少统一的规则。

<img src="assets/293aba0eb878abc7.png" alt="image-20260914092956158" style="zoom:67%;" />

接下来，我们就把这个文件夹交给 Codex 进行整理。

不过，在正式开始操作之前，有一个非常重要的步骤：**先做好备份。**

首先，将原文件夹完整复制一份，再把复制得到的文件夹设置为 Codex 的项目工作目录。这样即使 Codex 在整理过程中出现问题，原始文件夹也依然保留，能够将可能造成的损失控制在一定范围内。

项目设置完成以后，界面中会显示当前使用的项目文件夹。同时，左侧的抽屉栏里也会新增一个**“项目”**入口。

<img src="assets/b13d2431c868df1b.png" alt="image-20260914093100479"  />

### 第一步：让 Codex“只看不动”

完成项目设置以后，不要马上让 Codex 开始整理。第一步应该先让它查看文件夹中的实际情况，弄清楚里面到底有哪些内容。

你可以向 Codex 发送下面这段提示词：

```text
请先以只读方式盘点当前文件夹，具体要求如下：

1. 不移动、不重命名、不修改、不删除任何文件。
2. 统计当前文件夹中的文件类型、数量以及可能的用途。
3. 找出疑似重复、可能属于旧版本或用途不明确的文件。
4. 给出你对当前项目的初步理解。

请使用简洁的表格呈现盘点结果，并在最后列出需要我进一步确认的问题。
```

这段提示词中最重要的要求就是：

> 不移动、不重命名、不修改、不删除。

这一步可以理解为：让一名刚到岗的实习生先观察现场，再把自己看到和理解的情况完整复述出来。

你需要了解它看到了什么、认为你准备做什么，以及哪些地方还无法确定。通过它的复述结果，才能判断它的理解是否与你的真实想法一致。

Codex 完成盘点后，会告诉你读取了哪些文件，并统计不同类型文件的数量，例如 Word 文档、表格、TXT、MD、JPG 和 PDF 等。

同时，它还会帮助你找出可能存在的版本冲突。例如，有两个文件看起来都像最终版本，一个命名为“最终版”，另一个命名为“真的最终版”，究竟应该以哪一个作为主要版本？

对于这种无法直接确定的问题，Codex 不会强行替你做出判断，而是会将问题整理出来，交给你进一步确认。

除此之外，它还会根据现有内容给出对项目的初步理解，例如哪些文件可能是核心方案、哪些属于宣传素材，以及哪些可能只是过去保留下来的旧版本。

这一步非常关键。在真实的工作场景中，不应该让 AI 刚接触文件夹就立即开始整理，而是要先让它把现场情况说明清楚。如果它连文件夹中的实际内容都描述不准确，就不应该继

<img src="assets/e98387044ea8d4b9.png" alt="image-20260914093138015" style="zoom:80%;" />

### 第二步：只制定方案，暂不执行

Codex 完成文件夹盘点以后，下一步仍然不是直接开始整理，而是先让它制定一份完整的整理计划。

你可以把这个过程理解成：先让 Codex 写出一份“房间收拾方案”，等你查看方案并确认没有问题以后，再允许它正式动手。

进入计划模式后，可以输入下面这段提示词：

```text
请根据刚才的盘点结果制定一份文件整理方案，但暂时不要执行任何操作。

方案需要包含以下内容：

1. 建议创建哪些文件夹。
2. 每个文件应该移动到什么位置。
3. 文件需要采用怎样的命名规则。
4. 无法准确判断的文件应统一放入“待确认”分类。
5. 需要生成哪些说明文档和整理日志。
```

<img src="assets/801b1755dd7cac89.png" alt="image-20260914093228522" style="zoom:80%;" />

开启计划模式以后，Codex 会持续分析任务并制定具体方案，但不会真正执行任何操作。

它会先明确文件整理的基本原则，例如：**不删除、不覆盖、不合并**。如果发现同名文件，Codex 会暂时停止处理，并将相关文件记录到“待确认清单”中。

接下来，它会规划项目的根目录结构，例如创建“策划方案”“会议纪要”“宣传文档”和“视觉素材”等文件夹。

在“视觉素材”文件夹下面，还可以进一步建立“海报”“嘉宾照片”和“二维码截图”等子目录，让整个项目的文件层级更加清晰。

如果完全依靠人工处理，这种目录结构需要自己规划、逐个创建文件夹，再手动移动文件，整个过程会比较麻烦。

但对于 Codex 来说，只要前期制定的整理方案足够清楚，它就可以按照方案继续完成后续操作。

# 如何使用计划模式与追求目标

## 认识两个重要功能：计划模式与追求目标

这一节课，我们将进一步认识 Codex 中的两个功能按钮：**“计划模式”与“追求目标”**。

在默认情况下，这两个功能都处于关闭状态。很多人第一次看到它们时，可能不会特别关注，甚至会直接略过。

但实际上，这两个按钮都是 Codex 中非常值得掌握和使用的重要功能。

<img src="assets/4b316bec1d635c25.png" alt="image-20260914093641499" style="zoom:67%;" />

## 什么是计划模式

简单理解，**“计划模式”强调的就是先把事情考虑清楚，再开始执行。**

开启计划模式以后，Codex 不会立即修改你的文件，而是会先完成下面三件事情：

1. 分析并理解你提出的任务。
2. 收集完成任务所需的上下文信息，必要时向你提出问题。
3. 制定一份具体的执行方案，等待你检查和确认。

## 普通模式与计划模式有什么区别

我们可以通过一个简单的例子，对比普通模式和计划模式的不同。

在普通模式下，当你对 Codex 说“帮我修改这个项目”时，它可能会直接读取相关文件，并开始进行修改。

在计划模式下，即使你提出的是同一个要求，Codex 也会先告诉你：它准备将任务分成哪些步骤、需要查看哪些文件、有哪些问题需要你确认，以及执行过程中可能存在什么风险。

但是在这个阶段，它不会直接修改你的文件。

这就像你临时找了一名工人到家里装修。普通模式下，工人刚进门就拿起工具开始施工；计划模式下，工人会先向你说明准备如何改造，等你确认方案以后再正式开工。

## 什么时候应该开启计划模式

遇到下面几种情况时，建议开启计划模式：

- 准备使用 Codex 开发一项新功能。
- 自己暂时还没有想清楚应该如何描述需求。
- 担心 Codex 没有理解要求就直接修改文件。

## 配合计划模式使用的提示词

开启计划模式后，还可以在输入框中加入下面这段提示词，进一步明确你的要求：

```text
请先不要修改任何文件。

先阅读并了解当前项目的整体结构，然后告诉我你准备如何处理、需要我确认哪些问题。等我确认方案以后，再开始正式执行。
```

这里需要特别提醒大家：**提示词并不存在唯一的标准答案。**

上面这段内容只能作为一个参考。在实际工作中，应该结合自己的具体需求灵活调整，而不是完全照着模板直接使用。

## 什么是追求目标

了解完计划模式以后，我们再来看一下**“追求目标”**。

如果说计划模式解决的是“先把具体做法想明白”，那么追求目标强调的就是“围绕一个长期目标持续推进，直到把任务完成”。

当你为 Codex 设定好目标以后，它会围绕这个目标不断向前执行。只有在遇到需要你提供信息或进行确认的环节时，它才会暂停下来向你询问。

因此，追求目标更加适合步骤较多、执行流程较长的大型任务。

## 计划模式与追求目标如何配合

计划模式和追求目标并不是只能选择其中一个。更合适的使用方法，是让两个功能相互配合。

我比较推荐按照下面的节奏操作：

1. 先开启**“计划模式”**，让 Codex 帮你分析需求并拆分任务。
2. 检查 Codex 给出的计划，确认方案没有问题。
3. 再开启**“追求目标”**，让 Codex 按照计划持续执行，直到完成任务。

按照这种方式使用，既可以避免因为需求描述不清楚而导致 Codex 随意修改文件，也不需要你一直盯着每一个执行步骤。

以后可以用下面两句话记住它们的区别：

- 还没有想清楚具体应该怎样做，就开启**“计划模式”**。
- 已经明确最终目标，希望 Codex 持续完成任务，就开启**“追求目标”**。

## 实战案例：使用 Codex 整理一份混乱的订单表

仅仅了解概念还不够，接下来我们直接通过一个实际案例，看看具体应该怎样操作。

### 任务背景

假设某个文件夹中存放着一份订单表，但这张表属于比较典型的脏数据，其中存在以下问题：

- 部分订单号重复。
- 日期格式没有统一。
- 表格中包含错误值。

如果完全依靠人工整理，就需要自己完成数据筛选、重复值检查、格式修改和数据汇总等操作。

对于刚开始接触数据处理的人来说，这些步骤本身并不算特别困难，但整个过程会比较繁琐。

而 Codex 比较擅长处理的，正是这种**操作步骤较多，但处理规则能够明确说明**的任务。

这次实战的目标是：先让 Codex 理解订单表中的数据，根据现有问题制定清洗计划，再围绕任务目标持续执行，最终得到一份整理干净的表格和相应的分析结果。

![image-20260914093923009](assets/044f6383a77ce09f.png)

### 第一步：配置项目文件夹并开启计划模式

首先打开 Codex，将存放这份脏数据表格的文件夹设置为当前项目路径。

项目文件夹配置完成后，开启**“计划模式”**，然后向 Codex 发送下面这段提示词：

```text
请暂时不要修改任何文件。

当前项目文件夹中有一份内容比较混乱的表格。我的目标是将它整理成一份干净、规范的表格，并生成一份简单的数据汇总。

请先检查项目中的文件结构，然后告诉我：

1. 这份表格可能存在哪些问题？
2. 你准备按照哪些步骤清洗数据？
3. 清洗过程中会生成哪些新文件？
4. 有哪些内容需要我进一步确认？
```

### 第二步：确认计划并开启追求目标

查看 Codex 制定的计划并确认没有问题后，可以发送下面这段提示词，让它正式进入任务执行阶段：

```text
我已经确认这份计划，现在请进入追求目标模式。

任务目标：

1. 将原始表格整理成一份干净、规范的订单表。
2. 生成一份订单数据分析结果。
3. 使用美观的 HTML 网页展示订单分析结果和可视化图表。

完成标准：

1. 不修改原始文件。
2. 生成一份清洗后的数据表格副本。
3. 将日期统一为标准的日期格式。
4. 将金额统一转换为数字格式。
5. 删除明显重复的订单，并保留第一条记录。
6. 统一商品名称。
7. 生成 summary.md 文件，内容包括总订单数、总销售额、各商品销售额以及异常数据说明。
8. 任务完成后，告诉我具体修改了哪些内容，以及还有哪些地方无法确定。
```

这里有一个细节需要特别注意：我们在提示词中同时强调了**“不修改原始文件”**和**“生成清洗后的数据副本”**。

这是一个非常值得养成的习惯。始终保留原始数据，只让 Codex 对复制出来的文件进行操作。即使处理结果出现问题，也可以随时返回原始文件进行检查和对照。

# 什么是插件plugin

这节课，我们来了解一下 Codex 中两个非常关键的功能：插件 Plugin 和技能 Skill。

打开 Codex 的主界面，先看左上角，那里有个【插件】入口。点进去之后，就能进入插件页面。而在插件页面旁边，还有一个按钮，叫【技能】。

![image-20260916085153074](assets/032a540fded7f8a8.png)

## 插件和技能有什么区别

- **插件 plugin**

  说白了，就是给 Codex 接上外部工具。这样一来，Codex 就能完成很多它原本做不到的事情。比如生成 PPT、Word、Excel，或者连接你的谷歌邮箱、微软邮箱，让 Codex 帮你读取收件箱里的邮件。

  你可以把插件理解成手机上的 App。手机本身能力有限，但装上了各种 App 之后，就能点外卖、导航、聊天。插件对于 Codex 来说，也是同样的道理。

- **技能 skill**

  它是让 Codex 记住一整套固定的做事流程。

  举几个例子。你可能经常需要写公司新闻稿，把笔记整理成团队项目计划，或者按照固定格式生成周报。这些事情都有一个共同点：规则差不多，格式差不多，标准也差不多。

  再打个比方。假如你和 Codex 配合，完成了一次特别出色的工作。你肯定希望以后都能这么干。但问题是，如果每次都重新跟 Codex 解释一遍流程，那就太麻烦了。这时候，你就可以把这件事做成一个 Skill，相当于把这套流程写成一份说明书，保存起来，以后随时调用。

## 插件怎么安装

进入插件页面之后，你能看到自己之前安装过的插件。想安装新插件也很简单：找到目标插件，然后点击它右侧的【添加】按钮就可以了。

装好插件之后，下一步自然就是要学会怎么用它。

# 什么是技能 Skill

接下来，我们一起聊一下技能 Skill。

![image-20260916085914256](assets/d8ca94a242575e19.png)

先问你一个问题。你有没有碰到过这样的情况：同一件事，每回都得按照一样的格式、一样的规则、一样的标准去做。要是每次都重新跟 AI 解释一遍流程，那确实挺烦的。

Skill，就是拿来解决这个“固定流程”问题的。

## 技能 Skill 到底是什么

说得直白一点，Skill 其实就是一段文本。里面记的，是做某件事的方法，还有需要留意的细节。

你可以把它当成一份操作手册，或者一张写好的菜谱。新员工入职的时候，公司一般都会给他一份工作流程说明，告诉他这件事该怎么做，有哪些坑要避开。Skill 对 Codex 来说，就是这么一份说明。

你写一次，存起来，以后 Codex 每次执行这件事，都会照着这份说明来做，你就不用反复啰嗦了。

## 打开看看技能里到底写了什么

你只要随便点开一个 skill，就能看到里面写了大量的英文内容。这些啊，其实都是给 AI 看的。

如果你想知道这段英文到底在说什么，你可以直接把这段文本复制出来，发给任何一个 AI，让它帮你翻译成中文。这样，你也能搞清楚这份说明书里到底写了哪些规则。

![image-20260916090044660](assets/2b715c810bbd62e9.png)

# 用 Skill 保存你的 Codex 工作流

接下来，我们通过一个真实案例，带你看看 Skill 到底怎么创建，又该怎么调用。

## 从一次性任务，到反复出现的任务

假如我们之前让 Codex 自由发挥，去清洗且处理过一份Excel文件中的脏数据。这里有个关键问题：那次的清洗，是一次性的。

如果你的数据来源是固定的，比如你每周都要处理同一种格式的订单表，你自己心里也有一套清洗流程。这种情况下，你完全可以把这套流程原原本本告诉 Codex，然后让它把这套流程做成一个 Skill。这样一来，规则就不用每次重新说一遍了。

**清洗任务**

我上传了一份 Excel 表格，里面同样有不少脏数据。我给 Codex 的提示词是这样的：

```
 请帮我整理这份Excel数据表
 要求：
  1.不修改原始文件；
  2.生成清洗后的数据；
  3.日期统一成YYYY-MM-DD；
  4.金额统一成数字；
  5.删除重复订单；
  6.商品名称统一；
  7.生成summary.md，汇总订单数、销售额、各商品销售额和异常数据。
```

Codex 这次做完了，效果也不错。但问题来了。

## 问题来了：以后每周都要这样做吗

如果我以后每周都要整理一次订单表，难道每次都要重新打一遍这么长的提示词吗？

显然不现实。这里有个简单的判断标准：当一个任务不是只做一次，而是以后会反复出现，那就值得把它做成一个 Skill。

做成 Skill 之后，你不需要每次重新解释规则。只要调用这个 Skill，Codex 就知道该怎么做了。

## 让 Codex 创建一个订单整理 Skill

让 Codex 帮你创建一个订单整理 Skill

接下来，我们就把刚才这次清洗数据的对话，变成一个固定的流程，也就是一个 Skill。

操作很简单。先把输入框切换到英文输入法，然后输入一个【$】符号。

这时候，输入框上方就会跳出一堆可以调用的 Skill。这些 Skill 是 Codex 自带的系统 Skill，相当于内置的“老师傅”。

其中有一个叫【skill-creator】，顾名思义，就是“技能创造者”。官方文档里也提到过，可以用它来创建 Skill。它会自动收集你的工作流程信息，生成对应的 Skill，并帮你验证结果是否可用。

我们就选中【skill-creator】，再把下面这段提示词一起复制过去：

![image-20260916091204692](assets/d430db06d2a5d11a.png)

```
$Skill Creator
请帮我创建一个Skill，名字叫excel-cleaner。
它的功能和用途呢，就是基于我们这次的对话，完整对话来帮我清洗数据
请先帮我生成这个Skill 的说明文件，并告诉我以后该如何调用它。
```

## Skill 创建好了，要怎么调用它

等你的自定义 Skill 创建完成之后，调用方式同样简单。

只需要在对话框里按【$】，然后选中你刚刚创建好的 Skill，再告诉它要处理哪个文件就行：

```
$order-cleaner 请处理这个文件：orders_raw_june .csv
```

这一次，你会发现不一样.你会注意到，这一次我没有重新写一大堆规则。因为规则已经被保存进 Skill 里了。

你只需要告诉 Codex 两件事：用哪个 Skill，处理哪个文件。剩下的，它自己就知道该怎么做。

## 小结

最后呢，我们来对比总结一下：

第一，插件 Plugin 不是提示词，它是给 Codex 接入外部工具。

比如 Gmail、Google Drive、Slack、Sheets 这些。

第二，Skill 也不是普通提示词，它是把一套可重复的工作流程保存下来。

比如订单整理流程、周报生成流程、课程文稿优化流程。

第三，真正厉害的用法是插件 + Skill。

插件负责拿资料，Skill 负责按你的方法做事。

# 工作原则

## 理解优先

- 接到任务后，先理解目标、约束和最终产出。
- 不要只执行表面指令，要理解大哥真正想解决的问题。
- 如果需求存在明显歧义，先说明自己的理解和假设。
- 涉及重大方向选择时，给出利弊分析。

## 修改原则

- 默认最小改动。
- 优先复用已有代码、工具、结构和流程。
- 不进行无关重构。
- 不扩大修改范围。
- 每一次修改都必须能够对应到：
  - 用户需求
  - 已确认假设
  - 必要修复
  - 验证结果

## 分析原则

- 不把猜测当成事实。
- 未验证的信息必须明确说明。
- 遇到多个可行方案时，需要说明：
  - 推荐方案
  - 原因
  - 风险
  - 替代方案

## 执行原则

- 简单任务直接执行。
- 复杂任务先给简短计划，再开始执行。
- 多文件修改、架构调整、复杂排查，需要先说明执行步骤。
- 完成任务后说明：
  - 修改了什么
  - 为什么这样改
  - 如何验证
  - 还有哪些未验证风险

# 项目连续性

- 长期项目需要维护上下文。
- 优先读取已有项目记忆、说明文件和相关配置。
- 不要重复询问已经存在的信息。
- 如果发现历史规则与当前需求冲突，指出冲突并让大哥确认。

# 技术顾问职责

小弟不是单纯执行工具，而是大哥的技术助手。

需要主动：
- 发现方案漏洞。
- 提醒隐藏风险。
- 优化工作流程。
- 提出更高效的方法。

但：
- 不擅自改变目标。
- 不替大哥做未经授权的方向决策。
- 不因为觉得更优就偏离原需求。

# 输出习惯

回复格式：

开头：
“大哥，……”

分析时：
“小弟检查后发现……”
“小弟建议……”
“小弟认为……”

完成任务：
“小弟已经完成……”
“验证结果如下……”

避免：
- 过度客套。
- 长篇重复。
- 无意义总结。
- 模板化废话。

# 特殊规则

- 代码、变量名、接口名、目录名遵循项目原有风格。
- 不因中文沟通修改技术命名。
- 修改代码前阅读相关文件。
- 涉及运行逻辑、公开接口、构建、测试时必须验证。
- 不执行危险操作而不说明影响。
- 不删除重要文件或数据而不确认。

帮助大哥快速、高质量完成：
- Codex 工作流建设。
- Skill 设计优化。
- 小说/剧本生产流程开发。
- AI 视频生产流程开发。
- 自动化工具搭建。

## 开发计划

### 第五步：指定产品需求文档

该需求文档就是APP的施工说明图，以后即使你更换智能体、切换了新对话或者更换了新模型等等情况发生后，只要有这个需求文档在，那么我们后面AI工作流程就不会跑偏。

执行如下指令：

```
请把刚才已经确认的内容整理并保存为 PRD.md，作为后续开发依据。
PRD需要保留：
1.产品目标和使用场景
2.整体页面框架和导航结构
3.首页的内容结构
4.每个模块的用途
5.每个模块第一版最必要的数据和操作
6.本地数据文件、备份和恢复要求
7.第一版必须完成的功能
8.第一版暂时不做的功能
9.可以实际检查的验收标准
```

### 第六步：制定开发计划

执行如下指令：

```
根据当前的PRD.md，给出一份详细、可以直接执行的开发计划。
```

如果你没有开发背景的话，这个开发计划你可能看不懂。因为这个开发计划目前主要是给AI看的。可以让AI后续开发过程可以有标准、有计划的进行开发任务。

### 第七步：进行开发任务并验收

执行如下指令：

```
请根据开发计划开始开发。

按照计划顺序一步一步连续完成。每完成一个阶段，都要添加并运行对应的有效测试；测试失败就先定位并修复，通过以后再继续下一阶段。

持续执行，直到开发计划全部完成。

不允许通过删除测试、跳过测试或降低验收标准让测试通过。

全部完成后，运行所有测试。
```

等待过后，AI就帮我们开发完成了第一版APP的开发了。然后我们需要将APP完整的过一遍查看哪些功能还可以有改进的地方，可以先逐条记录下来。

### 第八步：让 Codex 帮你检查测试网页

第一版做出来后，它到底能不能用、好不好用？这就得测一测了。

说到测试网页，这在过去可是个技术活儿。要检查一个网页和它的功能，往往需要很多专业知识。很多互联网公司还专门设了一个岗位，叫【测试工程师】，就是干这个的。

他们平时都在检查些啥呢？比方说：

- 核心功能能不能顺利跑通？
- 按钮点下去有没有反应？
- 用户填的内容，能不能正常提交？
- 不同页面之间，能不能正常跳转？
- 用户手滑操作错了，有没有及时的错误提示？

听起来是不是有点唬人？

**让 Codex 自己测试网页**

好消息是——到了 AI 时代，这些检查，现在也可以交给 Codex 帮你一起干了。

你只需要把下面这段提示词发给 Codex：

```
请你作为一名产品经理、前端工程师和测试工程师，帮我系统检查这个网页的效果。
请从以下角度进行测试和评价：
  1 .核心用户流程是否完整，用户能否顺利完成主要任务；
  2 .所有按钮、链接、表单、弹窗、菜单等功能是否正常；
  3 .页面交互是否清晰，包括hover、点击、加载、成功、失败、错误提示等状态；
  4 .用户异常操作时是否有处理，比如空输入、错误格式、重复点击、超长内容等；
  5 .页面在电脑、平板、手机端是否都能正常显示；
  6 .页面布局是否整齐，文字、按钮、图片、卡片是否有错位或重叠；
  7 .页面视觉风格是否统一，包括颜色、字体、间距、圆角、阴影、图标等；
  8 .页面文案是否清楚，用户是否能一眼看懂这个页面是做什么的；
  9 .是否存在明显的性能问题，比如加载慢、动画卡顿、图片过大等。
  
请你先列出发现的问题，再按照“严重问题/ 中等问题/轻微问题”分类，最后给出一份具体修改方案。
```

当Codex 给出它的修改方案之后，我们再告诉它：“按照你的检查结果，帮我开发出第二版。

### 第九步：Git代码存档

在第一版APP开发完成后，我们也进行了验收，如果发现有什么问题也逐条记录了要改进的项目功能或者细节。但是有时候，你让AI改完后发现还不如一开始的版本呢，因此每一个版本的APP存档就非常有必要了。有了存档后我们就可以随意切换使用不同存档对应的APP版本了。

首先检查自己电脑上有没有Git环境，没有就让AI代安装，发送如下指令：

```
检查当前电脑是否已经安装Git；
如果没有安装，请根据当前电脑系统没使用安全、正规的方式安装Git;
```

接下来需要初始化Git仓库，指令如下：

```
请在当前项目中初始化本地Git仓库。
```

将刚才开发的第一个版本的APP进行存档。发送如下指令：

```
创建Git提交
```

## 项目打包

打包机制可以统一描述为：

“Windows 目录式便携发布包：GUI 启动 EXE + `_internal` 内置运行环境”

它的核心特点是：

- 不是单文件 EXE。
- 不是安装程序。
- 不使用 IExpress 或运行时自解压。
- 用户完整解压文件夹后，只需双击主 EXE。
- 主 EXE 不显示黑色命令窗口。
- Node.js、Python、FFmpeg、CLI 和项目资源全部放在 `_internal`。
- 用户电脑不需要安装开发环境。
- 启动失败必须显示错误提示，并保存日志。
- 不携带开发电脑的 API Key、项目数据和用户素材。

下次可以直接把下面这段话发给 Codex：

> 请把当前项目打包成“Windows 目录式便携发布包”，参考 PyInstaller onedir 的发布结构，但根据当前项目技术栈选择合适实现。  
>
> 最外层只保留一个供用户双击的 Windows GUI 启动程序 `项目名.exe`，其余项目代码、Node.js、Python、FFmpeg、CLI、依赖和资源全部放入 `_internal` 目录。  
>
> 不要制作单文件自解压 EXE，不要使用 IExpress，不要依赖 CMD 启动脚本，不要要求用户安装 Node.js、Python 或 FFmpeg。用户完整解压文件夹后，双击 EXE 即可启动程序。  
>
> GUI 启动器需要负责设置运行环境、启动本地服务、等待健康接口成功、自动打开浏览器、防止重复启动，并在启动失败时显示明确错误和日志路径。  
>
> 打包时不得包含本机 API Key、登录凭据、日志、项目数据或用户素材。最终必须在一个全新目录中完整解压并进行真实启动验证，不能只验证编译、文件存在或 EXE 能打开。

如果想说得更简短，可以直接说：

> 按“PyInstaller onedir 风格”打包：一个无黑框的 GUI 启动 EXE，加一个 `_internal` 内置运行环境目录，完整解压后双击即用，不做单文件自解压程序。

## AI⽣图的核⼼操作

接下来，我们就以电商场景为例，⼿把⼿带你学习更多 GPT Image ⽣图模型的实⽤技巧。电商是落地最快、收益最直接的场景之⼀，⾮常适合⽤来⼊⻔上⼿。

![image-20260919094001052](assets/bbc768690e6db77f.png)

你看这张玻璃杯的商品图，不是⽤相机拍的，也没有打开任何修图软件。我只是在 ChatGPT ⾥，把⾃⼰想要的画⾯⽤⼤⽩话说出来，它就帮我⽣成了这张图⽚。

学完这⼀章，你可以让它帮你⽣成商品图、换背景、添加⽂字、参考喜欢的图⽚重新设计，还可以修改图⽚⾥的局部内容。它就像⼀个随时待命的图⽚魔法师，你说它画，你改它调。

从这⼀节开始，我们就来学习怎么⽤ ChatGPT 制作图⽚、保存图⽚，以及精准地提出修改建议。不过先别急着上复杂的。

这⼀节只完成⼀件事：从零⽣成第⼀张玻璃杯电商图，⾛完最⼩闭环，先跑通再说。

### 第⼀步：⽤⼀句话⽣成图⽚

先打开 ChatGPT，在左上⻆切换到【ChatGPT】界⾯。

这⾥顺便说⼀下：不管你⽤的是 ChatGPT 还是 Codex，背后⽣图调⽤的都是 ChatGPT 内置的图像模型，⽣成质量完全⼀样。唯⼀的区别是，⽤ ChatGPT 来⽣图，不会消耗 Codex 的⽤量。所以⽣图这件事，建议直接在 ChatGPT ⾥做。

好，进⼊对话框以后，你不需要先学什么绘图术语。直接告诉它"请⽣成⼀张图⽚"，再说你想画什么就⾏。

我们先输⼊最简单的⼀句话：

```
请⽣成⼀张玻璃杯的电商商品图。
图⽚⽐例为 1:1，使⽤真实的商业产品摄影⻛格。
```

图⽚出来以后，先别急着评价好不好看，先看⼀眼：玻璃杯是什么形状？放在哪⾥？背景是什么颜⾊？画⾯⾥有没有其他东西？

这些内容，我们刚才都没有说，所以 ChatGPT 只能⾃⼰决定。

所以，简单提⽰词可以让我们快速看到第⼀版，但如果希望结果更接近脑⼦⾥的画⾯，就要把关键要求说得更清楚。⽐如图⽚的⽐例、⻛格、背景等等

![image-20260919094440291](assets/8ec7fe081d841c50.png)

### **第⼆步：把模糊要求变成明确要求**

接下来，我们升级⼀下提⽰词，换成下⾯这段:

```
请⽣成⼀张透明玻璃杯的电商场景图。

图⽚⽤途：电商商品展⽰图。
图⽚⽐例：1:1 正⽅形。

画⾯主体：
⼀只简洁的透明直筒玻璃杯，杯⼦完整展⽰，不要裁切。

场景和构图：
玻璃杯放在浅⾊⽊质桌⾯上，主体位于画⾯中央，占画⾯约三分之⼆。
背景⼲净，有少量虚化的绿⾊植物，但不要遮挡玻璃杯。

⻛格和光线：
真实的商业产品摄影，⾃然、⼲净、明亮。
使⽤柔和的窗边⾃然光，玻璃材质通透，反光和阴影真实。

限制：
不要添加⽂字、Logo、品牌、⽔印、⼈物和其他杯⼦。
不要让杯⼝、杯底和杯⾝发⽣明显变形。
```

![image-20260919094643553](assets/1b7441163a1aeacc.png)

这⼀次，ChatGPT 不只知道我们要画⼀个玻璃杯，还知道它放在哪⾥、⽤什么⽐例、画⾯是什么⻛格，以及哪些东西不能出现。

这条提⽰词看上去挺⻓，但其实不⽤死记。把它压缩⼀下，核⼼就是三组信息。

**第⼀组：告诉它这张图拿来做什么。**

⽐如"电商商品展⽰图"和"1:1 正⽅形"。⽐例就是图⽚的形状，1:1 是正⽅形。这只是本节的演⽰⽐例，不代表所有平台都固定⽤这个。真正制作时，要按照图⽚最终使⽤的位置来选。

**第⼆组：告诉它画什么，以及怎么画。**

这⾥包括玻璃杯的形状、摆放位置、背景、光线和画⾯感觉。注意，我们没有只写"画得⾼级⼀点"——因为每个⼈对"⾼级"的理解都不⼀样。我们写的是"浅⾊⽊质桌⾯、柔和⾃然光、⼲净明亮"。越具体，ChatGPT 越容易执⾏。

**第三组：告诉它什么不要出现。**

⽐如不要⽂字、不要品牌、不要⽔印、不要第⼆只杯⼦。这部分叫限制条件。它的作⽤就像给设计师划边界：可以发挥，但不要越线。

所以，⼀条⽣图提⽰词不需要写得多专业，但最好让 ChatGPT 看懂这三件事：这张图⽤来做什么，画⾯应该是什么样，以及哪些东西不能出现。

## 让GPT成为顶尖设计师

你看这⼏张苹果的照⽚，是我⽤⼿机随⼿拍的。

![image-20260919095941103](assets/d4cc61f83d8a72dc.png)

再看这张——这是 ChatGPT 根据那张照⽚，制作出来的电商场景图。

![image-20260919095947697](assets/cae60fdeaf744646.png)

这和上⼀节不⼀样。上⼀节的玻璃杯，是 ChatGPT 根据⽂字凭空想象出来的。这⼀节，我们开始⽤真实的商品照⽚来⼯作。

不过，照⽚上传以后，先别急着说"帮我做得⾼级⼀点"。

"⾼级""好看""有设计感"，这些词听上去没问题，但每个⼈的理解都不⼀样。ChatGPT 可能会给你⼀张很好看的图，却不⼀定适合你的商品和你的顾客。

所以这⼀节，我们换⼀种合作⽅式：先让 ChatGPT 像设计师⼀样问清楚需求，给出⼏个⽅向，等我们选好以后再开始画。

这⼀节的结果是：上传⼀张苹果照⽚，⾛完"提问 → 选⽅向 → ⽣成图⽚"的完整流程。

### 第⼀步：上传真实商品照⽚

上传照⽚之前，先注意三点：

1. 提供多个⻆度的照⽚，⽐如正⾯图、侧⾯图、俯视图，⻆度越丰富，ChatGPT 对商品的理解越准确；

2. 光线要充⾜，能看清产品细节；
3. 商品颜⾊和背景颜⾊要容易区分，不要拍成⼀团糊。

这三点做到了，后续⽣成的图⽚质量会好很多。

### 第⼆步：先让 ChatGPT 提问，不要⻢上画

照⽚上传以后，输⼊下⾯这段提⽰词：

```
你是⼀名电商视觉设计师。
我上传的是⼀个苹果的商品照⽚。
我希望把这张普通照⽚制作成适合商品展⽰的电商图⽚。
请先不要⽣成图⽚。
我们先⼀起讨论并确认下⾯五个问题：
1. 图⽚准备使⽤在什么场景；
2. 图⽚要突出什么特点；
3. ⽬标顾客是谁；
4. 需要什么⽐例和视觉⻛格；
5. 商品有哪些内容必须保持不变。
我回答后，请给我 3 个明显不同的设计⽅向。
每个⽅向简单说明场景、配⾊、构图和光线，并提供⼀张样图
```

别⼩看这句话。它的作⽤，是把整个流程切成三步：先问清楚需求，再给设计⽅向，最后才动⼿画。

就像你去找装修公司，⼀个好的设计师不会⼀进⻔就拿起笔开始画，他会先坐下来问你：预算是多少？喜欢什么⻛格？家⾥住⼏⼝⼈？问完了才开始出⽅案。

我们让 ChatGPT 也这样做。

### 第三步：回答问题，让它给出三个⽅向

ChatGPT 提问完以后，我们来回答。

这⾥我这样回答：

```
这张图最终要放在淘宝的主图上
我最想让客⼾第⼀眼感受到：新鲜、⽔润、脆甜、个头⼤。⽬标客⼾是要送礼的，属于⾼端⽔果消费者，所以你要围绕这个⾼端消费送礼场景帮我做包装。
⽐例是1:1
视觉⻛格是⾼端进⼝⽔果。
因为苹果属于⾮标准化的农产品，所以只要突出它的特点就可以了，并不需要完整地保留我提供的参考图的所有细节。
```

回答完以后，ChatGPT 会根据你的需求，提供三种⻛格明显不同的设计⽅向，每种⽅向配⼀张样图，供你参考和选择。

这⾥你可以仔细⽐较⼀下三张样图，感受⼀下哪种⻛格最符合你对这款商品的定位。

### 第四步：选定⽅向，正式⽣成图⽚

选好以后，直接告诉 ChatGPT 可以开始了。

我告诉它：`` 我喜欢第三张的⾼端⽔果的⻛格设计，按照第三张帮我⽣成⼀套电商产品图。``

### 本节⼩结

这⼀节，我们学会了⼀个更聪明的⽣图⽅式，不是直接说"帮我做得好看⼀点"，⽽是分三步⾛：

1. 上传真实商品实拍图，注意⻆度、光线和背景；

2. 让 ChatGPT 先问清楚需求，再给出三个设计⽅向；

3. 选好⽅向以后，再让它正式⽣成图⽚。这个流程多了两步，但你会发现，最终拿到的图⽚会更贴近你真正想要的结果。

## 快速复刻爆款商品图

⼤家看⼀下这三张图。

![image-20260919100437250](assets/5712499d689ef90a.png)

第⼀张，是我从⼭姆找到的⻩⽠商品图；第⼆张，是我⾃⼰拍摄的苹果照⽚；第三张，是 ChatGPT 根据前两张图⽣成的苹果商品图。

⻩⽠图⽚负责提供构图、背景、光线和配⾊；苹果照⽚负责告诉 ChatGPT，我们真正要展⽰的商品是什么。

很多⼈把这个过程叫"仿制参考图"。但这⾥的"仿制"，不是⼀⽐⼀复制，更不是把别⼈的品牌、⽂字和⽔印换个商品继续⽤。我们参考的是构图和拍摄⽅法，再⽤⾃⼰的商品重新⽣成。

这节课，我们就完整⾛⼀遍这个流程。

### 第⼀步：去哪⾥找参考图

找参考图，最直接的地⽅就是各⼤电商平台——淘宝天猫、京东、拼多多、亚⻢逊都可以。这些地⽅的商品主图，代表了同类卖家在构图、背景和视觉⻛格上的普遍做法，很适合拿来参考。

### 第⼆步：怎么判断⼀张参考图适不适合⾃⼰

参考图不是越好看越合适。选参考图，主要检查3件事。

**第⼀，商品类别和图⽚⽤途要接近。**

苹果和⻩⽠虽然不同，但都属于新鲜农产品，都适合⾃然光、清爽配⾊、突出新鲜感的画⾯，所以可以互相参考。但如果你拿⻩⽠的图去参考⾐服、⽂具或⼩家电，AI 虽然也能帮你出图，但最终的宣传效果就未必对了。

**第⼆，主体要清楚，构图不要太复杂。**

背景、道具和⽂字越多，AI 越难判断该参考什么。越简洁的参考图，提取出来的视觉⽅法越准确。

**第三，不要选那些主要靠品牌、明星或促销⽂案吸引⼈的图⽚。**

我们真正需要的是背景、构图、⻆度、光线和配⾊。

举个例⼦：苹果公司的⼴告⼀向是极简⻛格，但那背后是铺天盖地的营销投⼊。对于中⼩卖家来说，如果你也照着极简⻛做主图，没有品牌背书，销量很可能让你后悔。

再⽐如雅迪请周杰伦代⾔，那他的⼴告⾥周杰伦才是最⼤卖点。但如果你敢在⾃⼰的商品图⾥放周杰伦的照⽚，那就是妥妥的侵权了。
