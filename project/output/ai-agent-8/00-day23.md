# 飞影数字人 · 教学案例 —— 需求分析与决策

> ## ⚠️ 定位更正（用户已澄清，优先级最高）
>
> 本项目的产物**不是**「给老师上课用的数字人工具」，而是**一个教学案例**——
> 用来在**课堂上给学生演示「如何基于飞影开放平台 API 做出一个数字人应用」**。
>
> 因此本文中所有「教学场景合规」「教师审核闸门」「未成年人隐私」「多租户」等
> **产品化**推导，应从"生产要求"**降级为"案例中可讲的知识点"**。
> 功能设计本身仍然有效，但评价标准变了：
> **从"生产健壮性"改为"流程完整性与可演示性"**。
>
> **用户明确的核心诉求**：
> - ✅ **图1 的上传克隆（人物视频 + 音色样本）是必须实现的主路径**
> - ✅ 图2 的下拉选择保留，作为公共素材的备选
> - ✅ 公共形象/音色数量少不是问题——重点是演示「自己上传素材」这条链路

> 阶段：**需求与架构分析**（基础版骨架已实现并通过 40 项自测）
> 输入：用户提供的 UI 稿 + 飞影开放平台 API V2 官方文档 + 官方 MCP 源码 + 本机实测数据
> 决策方式：用户授权「自行分析决策」，本文中标注「**决策**」的条目均为 AI 代为拍板，可随时推翻。

## 1. 已锁定决策（用户明确指示）

| 编号 | 决策 | 影响 |
|---|---|---|
| **D1** | TTS 使用**飞影公版音色**（`voice/list` 中 `type=10`），不引入外部商用 TTS | 无需 TTS Provider 抽象层；音频链路完全在飞影内闭环 |
| **D2** | **不做多平台分发**，该功能整块删除 | 消除最大风险项（小红书/快手无个人发布 API） |
| **D3** | **两个独立产品**：独立 UI、独立部署、独立数据；**先基础版，后进阶版** | 不做共享后端服务；但不允许重复实现飞影对接代码（见 §7） |
| **D4** | 应用场景锁定 **教学环节** | 所有「短视频运营」向功能必须替换为「教学内容生产」向功能（见 §2） |

## 2. 对原始 UI 稿的教学化修订

原稿（尤其图2）大量借鉴了短视频 MCN 的运营话术。教学场景的目的、受众、合规要求都不同，必须替换。

| 原稿元素 | 为何不适合教学 | **决策：替换为** |
|---|---|---|
| `对标视频 / 原始文案` | 抓取他人视频有版权与合规风险；教学不需要「对标」 | **讲稿来源**：手动输入 / 导入文档（DOCX / PPT / PDF / TXT） |
| `AI 重构爆款文案` | 「爆款」话术与教学语境冲突，且教学容错率低 | **AI 讲稿辅助**：知识点拆分、口语化润色、术语一致性检查 |
| `话题标签`（自动推荐） | 教学内容靠课程结构分发，不靠标签 | **课程元信息**：课程名 / 章节 / 知识点标签 |
| `分发平台`（抖音/视频号/小红书/快手） | D2 已删除；且平台无个人发布 API | **导出与交付**：MP4 下载 / SRT 字幕 / 封面 / 打包下载 / 二维码 |
| `封面模板`：爆款口播、春日增长、3个技巧 | 运营向模板 | **教学封面模板**：课程封面 / 章节封面 / 知识点封面 |
| `全自动流水线 AI` | 教学无人审核风险高，错误内容会直接进课堂 | **保留，但降级**：自动化只到「生成草稿」，**发布前强制教师确认** |
| 文案上限 `10000` 字（图1） | ≈40 分钟口播，远超数字人稳定时长，口型必然漂移 | **降为 3000 字**（≈10 分钟微课），超长引导去进阶版走分段 |
| 图1 强制上传人物视频 + 音色样本 | **堵死新用户**——没素材就走不下去 | **新增「零素材出片」路径**（公共数字人 + 公版音色） |

## 3. 基础版规格 —— 「一节微课」

**一句话定位**：一位老师，一段讲稿，一条微课视频。**目标 3 分钟内出片，零配置。**

### 3.1 用户路径（两条，必须都有）

| 路径 | 流程 | 面向 |
|---|---|---|
| **A · 零素材（默认，推荐）** | 选公共数字人 → 选公版音色 → 贴讲稿 → 出片 | 新用户、不想出镜的老师 |
| **B · 个性化** | 上传人物视频/照片克隆形象（+可选克隆音色）→ 贴讲稿 → 出片 | 想用自己的形象的老师 |

> **决策**：路径 A 是基础版的**默认首屏体验**。图1 原稿只有路径 B，这是产品级缺陷——基础版承担拉新职责，不能第一步就要求素材。

### 3.2 字段规格

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| 作品名称 | 文本 | 必填，≤30 字，默认「未命名微课」 | 用于资产命名与作品列表 |
| 口播文案 | 多行文本 | **必填，≤3000 字** | 原稿 10000 字已下调；实时显示预计时长（按 ~4.5 字/秒估算） |
| 数字人形象 | 单选 | 三选一 | ① 公共数字人（默认）② 上传视频克隆 ③ 上传照片克隆（**消耗积分，需二次确认**） |
| 音色 | 下拉 | 来自 `voice/list kind=2` | 公版音色（对应原稿「林夏/陈默/小满」） |
| 语速 | 滑杆 | 0.5 ~ 2.0，默认 1.0 | 映射飞影 `voice/edit` 的 `rate`（**字符串类型**） |
| 字幕开关 | 开关 | 默认开 | 教学场景字幕是刚需 |

- 步骤条改为：`① 选形象与音色 → ② 确认讲稿 → ③ 生成成片`
- 保留原稿的重要提示：「最终视频会朗读这里的文字，**不会朗读音色样本里的内容**」——这条澄清很有价值。
- **强制审核闸门**：点「生成」前必须让教师确认讲稿全文（尤其是 AI 辅助生成过的）。教学场景不接受静默直出。

### 3.3 右栏预览

- 形象预览卡（带素材检查状态徽标）
- 成片预览卡（生成完成后自动展示）+ **下载 MP4** / 下载 SRT

### 3.4 调用链（基础版）

```
路径A（零素材）：
  GET  voice/list?kind=2              → 取公版音色
  POST voice/edit                     → 设语速（可选）
  POST <创作·视频创作（文本驱动）>      → task_id
  → 轮询 <创作任务状态> 或 接收回调     → 成片 URL
  GET  <查询账户积分>                  → 成本核算

路径B（个性化，首次）：
  POST <上传文件·获取上传地址> + 上传   → file_id（或直接用公网 URL）
  POST avatar/create_by_video|image   → 克隆 task_id
  GET  avatar/task                    → avatar 标识（异步，需等待）
  → 之后同路径A

关键优化：素材指纹去重
  飞影文档明确「相同 URL 视为同一个数字人」，因此对素材做内容哈希，
  命中已克隆资产则跳过克隆，直接进第③步。
```

> **决策**：路径 B 的克隆结果必须落库复用。否则同一老师第二次生成又要等一遍克隆，成本与等待时间翻倍。

## 4. 进阶版规格 —— 「课程内容工厂」

**一句话定位**：一章课件，产出多支知识点视频 + 封面 + 字幕。

### 4.1 三栏工作台（沿用原稿结构，教学化改造）

**01 讲稿工作流**
- 讲稿来源：手动输入 / 导入文档（DOCX / PPT / PDF / TXT）
- `AI 讲稿辅助`：知识点拆分、口语化润色、术语一致性检查（**不是**「重构爆款文案」）
- 课程元信息：课程名 / 章节 / 知识点标签 / 视频标题（≤30 字）
- `保存并进入音频合成 →`

**02 音频合成**
- 音色：公版音色卡组（试听用 `voice/task` 返回的 `demo_url`）
- 语速滑杆 `1.0x`
- 生成策略：`整段生成` / `分段生成`
- ⚠️ 「导入外部音频」**决策：保留但降级为可选高级功能**（老师可导入自己录的音频）。默认隐藏，避免偏离 D1。

**03 数字人视频**
- 形象选择（公共数字人 / 已克隆资产 / 新建克隆）
- 分辨率与画幅（**待验证项，见 §9**）

**04 教学后期**（原「智能剪辑」）
- 字幕生成与校对
- 章节标记 / 知识点切片
- 片头片尾 / 校徽水印
- 音量标准化

> **决策**：把「智能剪辑」改名「教学后期」，并去掉 B-roll、动效音效等娱乐化能力——教学场景的价值在**字幕准确、切片可定位、水印规范**，不在炫技。

### 4.2 预览与交付（替换原「预览与分发」）

- 竖屏/横屏视频预览 + 时长与规格元信息
- 封面：教学模板（课程封面 / 章节封面 / 知识点封面）+ 自定义上传
- **交付方式（替代分发）**：下载 MP4 / 下载 SRT / 下载封面 / 批量打包 ZIP / 生成二维码（便于课堂扫码播放）

### 4.3 批量与全自动

- 一份课件 → N 个知识点 → N 个视频任务（批量提交，统一进度面板）
- 「全自动模式」**决策**：自动化范围限定为「讲稿拆分 → 音色语速套用 → 批量提交生成」，**产出物状态为「草稿」，必须教师逐条确认后才标记为「可交付」**。

### 4.4 「音频合成」步骤的降级预案 ★重要

**问题**：D1 定了 TTS 用飞影公版音色，但飞影的 TTS 是**内嵌在「视频创作（文本驱动）」里的**。飞影虽有 `音频创作` 接口，但我未能读到其参数，**无法确认它能否独立产出可复用的音频文件**。

| 情况 | 应对 |
|---|---|
| 飞影 `音频创作` 可独立产出音频 | 步骤 02 是真实流水线阶段：`音频创作` → 音频资产入库 → `视频创作（声音驱动）`。可试听、可换、可复用 |
| 不可（或只能产音频不能驱动） | 步骤 02 **降级为参数面板**（选音色 + 语速 + 试听），音频在视频任务内部生成，后端不产生音频资产 |
| `分段生成` 的实现 | 无论哪种情况都可行：拆成多个**文本驱动**任务 + ffmpeg 无损拼接。不依赖独立音频 |

> **决策**：进阶版按「降级预案」设计数据模型——音频资产字段**可空**。这样无论 §9 的验证结果如何，都不用返工。

## 8. 教学场景专有约束

**合规**
1. **AI 生成标识**：按《互联网信息服务深度合成管理规定》，对外使用的 AI 视频应添加标识。建议默认开启水印（`aigc_flag=1`），并在产品内说明。
2. **肖像与声音授权**：克隆真人形象/声音必须留存**书面授权**。教师克隆自己也要走一次授权确认勾选。
3. **未成年人**：若教学对象为 K12，**严禁**用学生素材做克隆；素材库需做年龄与身份提示。
4. **内容准确性**：AI 讲稿可能出错，**必须保留人工审核环节**，不可默认全自动直出。
5. **教材版权**：导入教材/课件内容时提示版权责任归属。

**体验**
- 字幕默认开启（教学无障碍刚需）
- 时长预期管理：显示"预计 3 分 20 秒"而非只显示字数
- 生成是异步的：必须做进度反馈 + 「完成后通知」，不能转圈死等
- 长内容引导：超过 3000 字引导至进阶版分段生成，而不是直接拒绝

## 2. 已确认端点

### 2.1 上传文件（两步，不走 JSON）

**Step 1 — 取预签名地址**
```
POST {base}/tool/create_upload_url
req  { "file_extension": "mp4" }
resp { "upload_url": "...", "content_type": "...", "file_id": "..." }
```

**Step 2 — PUT 原始字节**
```
PUT <upload_url>
Header: Content-Type: <上一步返回的 content_type>
Body:   文件原始二进制
期望:   200 或 204
```
→ 拿到 `file_id`，供后续 `file_id` 参数使用。

**支持的扩展名**：`mp4` `mov` `mp3` `m4a` `wav` `jpg` `jpeg` `png`

> ⚠️ 源码里 `content_type` 是**被服务端返回值覆盖**的，不是本地按扩展名推断的那个。照抄服务端返回值。

### 2.2 数字人克隆

```
POST {base}/avatar/create_by_video
req  { "title": "...", "video_url": "..." }  或  { "title": "...", "file_id": "..." }
resp { "task_id": "..." }

POST {base}/avatar/create_by_image
req  { "title": "...", "image_url": "..." }  或  { "title": "...", "file_id": "..." },
     "model": 1 | 2          # 1=视频2.0  2=视频2.1（默认 2）
resp { "task_id": "..." }

GET  {base}/avatar/task?task_id=...
resp { "status": 1|2|3|4, "avatar": "av_..." }    # status=3 时拿 avatar
```

> `model` 参数**仅 image 接口有**，video 接口没有。

### 2.3 音色

```
GET {base}/voice/list?kind=1|2
     kind: 1=自己克隆的   2=公版/公共声音
resp { "data": [ { "voice": "...", "type": 10|20|22|8,
                   "title": "...", "rate": "...", "volume": "...", "pitch": "..." } ] }
```

> **公版音色 = `kind=2`**。这就是「林夏 / 陈默 / 小满」这类音色的来源——**基础版零素材路径靠它**。

### 2.4 视频创作 ★主链路

```
POST {base}/video/create_by_tts          ← 文本驱动（基础版主链路）
req  { "avatar": "av_...", "text": "...", "voice": "声音ID", "title": "..." }
resp { "task_id": "..." }

POST {base}/video/create_by_audio        ← 音频驱动（进阶版）
req  { "avatar": "av_...", "title": "...", "audio_url": "..." }  或  { ..., "file_id": "..." }
resp { "task_id": "..." }

GET  {base}/video/task?task_id=...
resp { "status": 1|2|3|4, "video_Url": "https://..." }
```

**三条硬规则**：
1. **`video_Url` 是大写 `U`** —— 写成 `video_url` 会拿到 `undefined`。这是最容易踩的坑。
2. **`avatar` 是必填**。两个接口都要求先有数字人 ID，所以「零素材出片」的正确做法是：`avatar/list?kind=2` 取公共数字人 → 传给 `create_by_tts`。**路径成立，已验证可行。**
3. **`voice` 不传会随机挑一个公版音色**（源码里 `random.choice`）。教学产品**必须显式传 `voice`**，否则同一份讲稿每次生成音色都不同。

**音频文件限制**（`create_by_audio`）：`mp3` / `m4a` / `wav`，**≤20MB，时长 1 秒 ~ 3 分钟**。

## 3. 踩坑清单（开发时逐条对照）

| # | 坑 | 说明 |
|---|---|---|
| 1 | **`video_Url` 大写 U** | 最容易错，会导致成片 URL 取不到 |
| 2 | **任务查询是 `/video/task`** | 不是 README 写的 `/creation/task` |
| 3 | 上传是 **PUT 到预签名 URL** | 不是 POST 到自己的接口；期望 200/204 |
| 4 | 公版音色用 `kind=2` | `kind=1` 是自己克隆的 |
| 5 | `voice` 必须显式传 | 否则随机音色，结果不可复现 |
| 6 | **成片 URL 是临时的** | 必须**尽快下载落盘**，否则会失效 |
| 7 | 官方 MCP 代码**没有解析响应体 `code`** | 官方文档明确业务异常也返回 HTTP 200。官方自己只判 `status_code==200` + `task_id` 是否存在——**我们的 SDK 必须补上 `code` 解析**，否则会出现"看起来成功实际失败"的幽灵 bug |
| 8 | 上传 `content_type` 用服务端返回值 | 别用本地推断的 |
| 9 | 轮询超时 600s | 克隆 + 成片是两个串行异步任务，UI 必须做进度反馈，不能死等 |

| 6 | 免费 Token 的每日配额 | 决定联调节奏 |

## 7. 第二轮实测（用户 Token，成功跑通）

**结果**：完整产出一条真实视频。**其中两条结论推翻了此前的设计假设。**

### 7.1 成功的完整任务响应（`GET /video/task`，status=3）

```json
{
  "status": 3,
  "video_Url": "https://hfcdn.lingverse.co/.../5ca90152-....mp4",
  "duration": 90,
  "message": "",
  "code": 0,
  "request_id": "8NelQmoTMXYOhoG4"
}
```

**任务响应只有 6 个字段**：`status` / `video_Url` / `duration` / `message` / `code` / `request_id`。
⚠️ **响应里没有宽高** —— 分辨率只能用 `ffprobe` 探测。

失败态响应（status=4）：
```json
{"status":4,"video_Url":"","duration":0,"message":"积分不足","code":1002,"request_id":"..."}
```

### 7.2 关键实测数据

| 指标 | 实测值 |
|---|---|
| 文案 500 字 | ✅ **成功** |
| API 返回 `duration` | **90 秒** |
| ffprobe 实测时长 | 89.8 秒 |
| **语速换算** | **≈ 5.56 字/秒** → `秒数 ≈ 字数 ÷ 5.56` |
| **生成耗时** | **91.8 秒**（≈ 视频时长的 1.02 倍） |
| **输出分辨率** | **928 × 1664**（竖屏，**不是** 1080×1920） |
| 文件大小 | 23.9 MB / 90 秒（约 2.1 Mbps） |
| 成片 CDN | `hfcdn.lingverse.co` |

### 7.3 三个必须据此改设计的结论

**1. 🔴 画幅由「形象素材」决定，不是接口参数**
输出的 928×1664 正是所用公共数字人（驾校教练）**源视频的分辨率**。官方 MCP 的 `create_by_tts` **没有任何分辨率/画幅参数**。
→ **进阶版 UI 承诺的「1080×1920」无法通过接口参数实现。** 想要 1080×1920，只能自己克隆一个该分辨率的形象。
（保留不确定：不能排除存在未公开参数，但官方实现里确实没有。）

**2. 🟢 「500 字上限」是 MCP 自己的限制，不是 API 限制**
3000 字的请求**被正常受理**（返回了 `task_id`，排队 112 秒），失败原因是**积分**而非文本长度。若 500 是 API 硬限制，`create_by_tts` 会当场拒绝。
→ **基础版文案上限不必受 500 约束**，真正上限仍待测。

**3. 🔴 积分检查发生在异步处理阶段，不是提交阶段**
3000 字任务：提交成功 → 排队 112 秒 → **才**返回 `status=4 积分不足`。
→ 用户等了 2 分钟才被告知没积分，**这是严重的体验缺陷**。
→ 产品**必须做「提交前积分预检」**并据此拦截或提示。（需补齐「查询账户积分」端点。）

### 7.4 对既有决策的修正

| 原决策 | 修正 |
|---|---|
| 文案上限 3000 字 | **暂保留 3000**，真正上限仍未测出；基础版建议 2000~3000 字并显示预估时长 |
| 轮询超时 600s | ⚠️ **偏紧**。耗时 ≈ 视频时长 × 1.02 **+ 排队**。10 分钟视频会逼近上限，**建议改 1800s** |
| 时长估算 ~4.5 字/秒 | **改为 5.56 字/秒**（普通话音色实测值，其他音色会有差异） |
| 进阶版「1080×1920」 | ⚠️ **不可直接实现**，改为「由形象素材决定」或引导克隆目标分辨率形象 |

### 7.5 当前阻塞

要测出**真正的文案上限**和**更多分辨率样本**（尤其横屏），需要账号充值积分。
