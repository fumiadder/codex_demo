# 日历与记录联动设计（知序工作台）

日期：2026-11-12
范围：`workbench/public/app.js`、`workbench/public/styles.css`、`workbench/server.py`、`workbench/daily.py`、相关测试与 QA 脚本

## 1. 背景与目标

当前月历只渲染待办，日程列表虽然合并了待办与今日记录，但记录行没有图片，也没有任何标签筛选；今日记录的标签只有 AI 生成结果，用户无法在记录时手动勾选；待办不能附加图片。用户希望：

1. 日历日期格内直接看到内容，而不是只显示一个点或纯标题；
2. 日程里能看到图片；
3. 记录时勾选标签（如「学习」），之后能在日历和日程里单独查看某个标签的内容。

已确认的产品决策：

- 日历采用 C 布局：标题、首图、标签在日期格内完整展开；
- 图片统一「首图 + 总数」展示，点击首图查看全部图片；
- 标签筛选同时作用于月历和日程列表；
- 待办也可以上传图片，因此待办需要新增图片上传、存储、查看和删除能力；
- 后端采用扩展现有结构的方案：待办与今日记录仍分开存储，由前端合并为日历视图，不做数据模型迁移。

## 2. 非目标

- 不合并 `items` 与 `daily_entries` 两张表，不迁移历史数据；
- 不实现图片排序、封面选择、拖拽换位；
- 不改变 AI 识别流程；`meta.ai.tags` 仍只作建议，不进入筛选；
- 不新增跨空间聚合日程或服务端统一日程接口；
- 不改变现有权限模型：查看者仍只读。

## 3. 交互设计

### 3.1 月历日期格（C 布局）

每个日期格自上而下：

1. 日期数字（保留今天、选中、非本月灰化样式）；
2. 最多 3 条内容行，每条包含：
   - 状态点（待办完成态沿用现有 `is-done` 样式）；
   - 标题（单行省略，待办用 `title`，记录用 `title`，缺失时回退 `describeEntry`）；
   - 有图时在标题左侧或右侧显示 40×40 的首图缩略图，多图时叠加「N 张」角标；
   - 标签以小型 chip 展示，最多 2 个，超出显示「+N」；
3. 超出 3 条显示「+N」。

待办与记录混排：先待办（按开始时间，无时间排后），后记录（按创建时间）。点击内容行仍打开原有详情（待办进编辑器，记录进记录弹窗）；点击图片打开现有灯箱查看该条的全部图片；点击日期空白区域仍是选中/取消选中该日期。

移动端：单列、首图固定 40×40、标题单行省略、标签单行横向溢出隐藏，不改变日期格的基础网格与高度上限，避免重现此前三列挤压问题。

### 3.2 标签筛选条

- 日历页顶部（模式切换下方）显示与待办页一致的标签筛选条，复用 `renderTagFilterBar` 的视觉与「再点一次取消」交互；
- 选中标签后，月历日期格、日期详情面板、日程时间线同时只显示带该标签的待办与记录；
- 切换标签不改变当前月份、选中日期和日程滚动范围；
- 当前筛选下没有任何内容时：日期格保持空白但仍可点击；日期详情与日程显示明确空状态，文案指明是标签筛选导致；
- 标签数据来自 `GET /api/spaces/{sid}/tags`，聚合待办、笔记与今日记录的人工标签；AI 标签不参与。

### 3.3 日程时间线

- 每条待办与记录都显示首图缩略图与图片总数（有图时）；
- 记录行显示其人工标签 chip，最多 3 个；
- 日期分组仍按现有范围（默认今天前 7 天起 37 天）展示；
- 标签筛选生效时，跳过的空日期分组逻辑保持不变。

### 3.4 待办编辑器与记录编辑器

- 待办编辑器新增「图片」区域：选择图片后立即上传，展示缩略图、可单张删除；最多 9 张；新建待办时先保存待办再上传，上传失败给出提示但保留已创建的待办；
- 记录编辑器新增标签编辑器，复用 `buildTagEditor`（回车/逗号添加、× 删除、最多 8 个、每个 ≤20 字）；记录详情与记录卡片展示这些标签；
- 两类编辑器中的图片与标签都受写权限约束，查看者只读。

## 4. 数据设计

### 4.1 今日记录标签

- 存放位置：`daily_entries.meta` 增加 `tags: []`，不新增数据库列；
- 规则与待办一致：数组、去重后最多 8 个、每个 1–20 字；
- 创建与编辑接口接受 `tags`，缺省继承原值；旧数据没有 `tags` 时按空数组处理；
- `meta.ai.tags` 保持不变，不与人工标签合并；
- 人工修改标题/摘要时沿用现有 `meta.ai.applied` 行为，`tags` 不触发该标记。

### 4.2 待办图片

- 复用 `files` 表与私有 `uploads` 存储命名空间，`files.item_id` 指向待办 `items.id`，不新增表、不迁移数据；
- 每条待办最多 9 张；仅接受 `image/png`、`image/jpeg`、`image/gif`、`image/webp`，按文件头嗅探真实类型，不信任文件名与声明类型；
- 单文件沿用 25 MB 上限、上传并发闸门、空间与全站配额、`storage_jobs` 预留/发布流程；
- 读取统一走 `GET /api/files/{fileId}`，沿用现有鉴权与缓存策略；
- 排序按 `created_at, id`，首图即最早上传的一张；
- 删除待办时沿用现有 `DELETE /api/items/{id}` 中按 `item_id` 清理 `files` 与私有对象的逻辑，无需额外改动；
- `files` 同时服务媒体条目，接口返回 `images` 时只对 `kind = task` 的条目生效，避免改变媒体条目行为。

### 4.3 标签聚合

`space_tags` 在现有 `items` 聚合之外，追加扫描 `daily_entries.meta.tags`：

- 只统计 `meta.tags` 中的字符串；`meta.ai.tags`、`convertedSuggestions` 不统计；
- 仍兼容待办旧的单值 `meta.tag`；
- 输出结构不变：`{"tags": [{"name", "count"}]}`，最多 50 项。

## 5. 接口设计

所有写接口沿用现有会话语义、CSRF 校验、`membership(write=True)` 与容量检查。

### 5.1 今日记录

- `POST /api/spaces/{sid}/daily`：请求体新增可选 `tags: string[]`；
- `PATCH /api/spaces/{sid}/daily/{entryId}`：请求体新增可选 `tags: string[]`，整体替换；
- 响应 `entry.meta.tags` 直接返回，前端无需额外字段；
- 校验失败返回 400，文案与待办的标签校验保持一致。

### 5.2 待办图片

- `POST /api/items/{itemId}/images`
  - `multipart/form-data`，单文件字段名 `file`；
  - 仅所有者/编辑者可调用；条目必须存在且 `kind = task`；
  - 每张图片一条 `files` 记录，返回 `{"image": {...}, "images": [...]}`；
  - 超出 9 张返回 409；非图片、空文件、超限分别返回 400/400/413；
- `DELETE /api/items/{itemId}/images/{fileId}`
  - 仅所有者/编辑者；图片必须属于该条目；
  - 删除数据库记录后通过 `storage_jobs.queue_delete` 清理私有对象，返回 `{"ok": true, "images": [...]}`；
- `GET /api/spaces/{sid}/items` 与条目 PATCH 响应中，`kind = task` 的条目增加：

```json
{
  "images": [
    { "id": "...", "name": "a.png", "mime": "image/png", "size": 12345,
      "url": "/api/files/<id>", "createdAt": "..." }
  ]
}
```

列表接口用一次 `item_id IN (...)` 批量查询图片并按条目分组，避免 N+1。

## 7. 边界与错误处理

- 记录只有文字没有图片：正常显示标题与标签，不占位图片；
- 图片加载失败（401/404/网络）：显示灰色占位块，不打断日期格布局；
- 一条内容有 9 张图：日历与日程仍只显示首图 + 「9 张」，点击进灯箱查看全部；
- 标签重复或大小写不同：按现有规则去重，大小写视为不同标签（与待办一致）；
- 旧数据：没有 `meta.tags`、没有 `files` 记录的待办与记录照常显示；
- 记录被删除或待办被删除：标签数量在下次聚合时自动减少；私有图片随级联删除进入清理队列；
- 查看者：可看图片与标签，上传/删除接口返回 403；前端隐藏上传入口；
- 网络失败：沿用现有 toast 文案与重试方式，不做乐观假数据。

### 8.1 后端单元/接口测试

`workbench/tests/test_daily.py`：

- 创建记录接受 `tags`，写入 `meta.tags`，响应可见；

## 9. 风险与取舍

- **日期格高度增长**：C 布局必然比纯标题更高；用 40px 固定缩略图、最多 3 条、标签单行截断控制高度，移动端保持现有网格比例。
- **标签筛选状态共享**：`state.tagFilter` 目前被待办/笔记页共用，日历复用后跨页面仍保留同一筛选。符合「一个标签筛选」的直觉，但切换页面时需确认筛选条始终可见，避免用户困惑。
- **待办图片复用 `files`**：避免迁移，但 `files` 没有宽高与排序字段；本期不需要，若后续要做图片排序再单独设计。
- **新增接口的权限面**：上传/删除必须复用现有 CSRF、成员写权限、配额与清理队列，避免出现绕过配额或遗留孤儿对象。
