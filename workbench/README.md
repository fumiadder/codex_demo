# 知序 · 个人工作台

中文个人工作台第一版。独立账号与空间权限、工作／生活分区、任务和笔记、浏览器加密密码箱、媒体上传与预览、录音保存。应用没有外部字体、CDN、第三方登录或模型接口依赖，可部署在国内云节点；实际国内访问需部署后实测。

## 本地运行

需要 Python 3.12 或以上，无第三方 Python 包。

```bash
python server.py
```

打开 `http://localhost:8000` 并注册自己的账号。启动默认绑定地址和端口以服务输出为准。实际数据位于 `DATA_DIR` 指定的目录；默认本地 `data/`，此目录已从代码和部署包中排除。真实账号不会写入演示样例。

```bash
python -m unittest discover -s tests -v
node --check public/app.js
```

浏览器与容器验证详情见 `VERIFICATION.md`。可重复浏览器检查需要开发环境额外提供 Playwright 与 Chromium，生产运行不依赖它们。

## 国内云部署

可使用阿里云、腾讯云等提供的 Linux 云服务器。准备一个域名并将 DNS A 记录解析到服务器；按所选国内云厂商要求完成备案。开放 TCP 80、443；应用端口 8000 仅在 Docker 内部使用。此仓库不包含或创建云账号、付费资源、域名和备案。

在服务器安装 Docker Engine 和 Compose 插件，将此目录上传到服务器，然后：

```bash
cp .env.example .env
# 修改 .env 的 WORKSPACE_DOMAIN 为自己的域名
docker compose up -d --build
docker compose logs --tail=80
```

Caddy 会为已正确解析的域名申请 HTTPS 证书，浏览器通过 `https://你的域名` 访问。Docker 镜像获取和证书签发需要相应网络连通性。`TRUST_PROXY=1` 仅用于 Compose 中应用被 Caddy 隔离的场景；不要将应用端口直接暴露到公网并信任任意代理头。

证书签发及健康检查成功后，用两个真实账号验证独立空间、邀请、只读权限、媒体上传和播放，以及同一账号换设备后的数据同步。浏览器录音和 Web Crypto 密码箱要求 HTTPS 或 localhost。部署尚未执行时不能把本地验证当作国内网络验收。

## 数据与访问

- 每个账号有自己的空间。注册其他账号不会获得既有空间访问权。
- 空间所有者可按已注册成员的邮箱授予编辑或只读权限。协作不会改变成员各自的个人空间。
- 工作／生活是空间内记录的分区。共享一个空间会共享该空间内普通工作、生活记录；只想共享工作时应单独创建协作空间，把个人生活记录保留在个人空间。
- 密码箱按用户和空间保存浏览器生成的密文，不与普通协作成员共享。PBKDF2 与 AES-GCM 在浏览器执行，密码和明文不会发送给服务器。密码忘记后无法恢复内容；登录账号并不能解密密码箱。
- 用户账号密码只保存加盐派生值；服务器使用 HttpOnly 会话 Cookie、同源请求校验、空间成员授权和上传大小限制。文件下载也检查权限。
- 文件存储位于本地持久化卷，单个上传上限 25 MiB，默认每空间累计 1 GiB、全站 10 GiB，保留至少 100 MiB 磁盘余量。图片、音视频、PDF 可以预览；其他文件以安全下载提供。服务器运维者对普通记录和媒体具有基础设施层面的访问能力。
- 每账号最多 50 个自有空间，每空间最多 2000 条普通记录；达到容量时会提示，列表不会静默丢弃记录。部署方可通过 `MAX_SPACE_STORAGE_BYTES` 和 `MAX_TOTAL_STORAGE_BYTES` 调整文件总量。

## 语音与扩展

语音录入提供真实录音、试听和保存。自动转写使用浏览器支持的 SpeechRecognition，支持度和识别服务连通性由浏览器决定；它可能将语音发送到浏览器厂商服务。未支持时仍可录音并手动补充文字。部署方可按需接入国内语音识别服务。

模块库保留后续扩展入口，AI 模型、日历、账本等未配置项应明确展示待接入状态。本版没有伪造 AI 回复，也不会把模型密钥放进前端。接入模型、云语音或第三方应用时，将凭据配置在服务端并复用空间权限校验。

## 备份与维护

数据和媒体持久化于 `workspace_data` 卷。执行 `bash scripts/backup.sh` 会短暂停止应用并备份完整数据，之后自动启动。备份包含私人记录、媒体和密码箱密文，应放到受控存储。没有备份时不要使用 `docker compose down -v` 删除卷。

升级前先备份；替换代码后执行 `docker compose up -d --build`。不要修改运行中的数据库或共享文件目录。需要大规模协作、审计、恶意文件扫描、密码重置、邮箱验证、强制邀请注册或高可用时，应在这版基础上扩展，不能将当前最小版本视为具备这些能力。
