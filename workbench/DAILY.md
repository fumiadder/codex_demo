# 今日记录 · 图片速记与视觉识别

「今日记录」让用户用拍照或选图快速记下今天做了什么：原图存入当前空间的私有媒体管线，
服务端调用阿里云百炼视觉模型生成标题、摘要、标签和待办建议，并可把当天多条记录汇总成每日小结。
模块复用工作台的账号会话、空间成员权限、CSRF 校验、存储配额和私有文件访问，不另建孤立应用。

## 功能边界

- 每条记录 0–9 张图片加一段可选附言，支持工作／生活分区，按 Asia/Shanghai 自然日分组。
- **保留原图**：上传的是原始图片，识别时由服务端用 Pillow 把原图降采样为内存中的 JPEG
  识别副本（最长边 1600px、质量 85；总体过大时降到 1280px、质量 78），副本不落盘、不替换原图。
- 识别结果只作辅助：首次成功识别自动填充标题与摘要；用户手动编辑后，重新识别的结果只写入 `meta.ai`，
  需要点击「采用识别的标题与摘要」才覆盖展示字段，重识别不会冲掉人工内容。
- 待办建议可一键转成现有待办事项（`kind=task`），已转换的建议在卡片上明确标记并禁用重复点击。
- 每日小结把当天 active 记录的标题、摘要、附言汇总为不超过 300 字的小结，按「空间 + 日期」保存，可重新生成。
- 未配置模型密钥时：上传、建条目、时间线、灯箱、手动编辑全部可用；所有 AI 入口明确显示「待连接」，
  不显示伪造识别结果。

## 服务端配置

视觉能力与晚安故事共用同一个 `DASHSCOPE_API_KEY`（百炼中国内地固定端点，兼容模式 Chat Completions）。
2026 年起 `qwen3.8-flash`、`qwen3.7-plus`、`qwen3.8-max` 原生支持图像输入与 `response_format=json_object`
结构化输出，无需单独开通 VL 模型。密钥只存在服务器 `.env`，不写入源码、页面、发布包或日志。

| 变量 | 用途与默认值 |
| --- | --- |
| `DASHSCOPE_API_KEY` | 与晚安故事共用的百炼密钥；空值关闭图片识别与每日小结，记录功能不受影响 |
| `VISION_ENABLED` | 默认 `1`；只有 `1` 允许调用视觉模型，设 `0` 可独立关闭 AI，图片记录仍可用 |
| `VISION_MODEL` | 默认 `qwen3.8-flash`（成本优先）；可选 `qwen3.7-plus`、`qwen3.8-max`。未知值直接关闭视觉，**不回退、不替换其他可能计费的模型** |

分阶段启用：先在百炼核对视觉模型余额与有效期，建议开启「免费额度用完即停」，再在 `.env` 填写密钥。
应用开关只控制是否发起请求，不能替代供应商的额度停止机制。配置有效仅代表具备调用条件，不代表额度或网络已确认；
应用不会创建任何云付费资源，也不自动填入密钥。调用可能产生供应商用量费用。

## 接口约定

所有接口前缀 `/api/spaces/:spaceId/daily`，复用中央登录态、`X-Requested-With` CSRF 校验和空间成员权限：
非成员 404、只读成员写入 403、未登录 401。图片和条目跟随空间权限（个人空间仅本人可见，共享空间成员可见）。

| 方法 | 路径 | 说明 |
| --- | --- | --- --- |
| GET | `config` | 返回视觉可用态、模型、图片上限与允许的 MIME |
| POST | `uploads` | 单图 `multipart` 两阶段上传，服务端按魔数嗅探真实图片类型并读取尺寸 |
| POST | `entries` | 用暂存图片 ID（0–9）加附言建记录，事务内把暂存图转成记录图片 |
| GET | `entries?date=` 或 `?month=` | 按自然日或月份列出记录（月份上限 500 条），含当日小结映射 |
| GET | `entries/:id` | 单条记录详情 |
| PATCH | `entries/:id` | 编辑标题/摘要/附言/分区/状态，或 `applyAi` 采用识别结果、回写已转待办 |
| DELETE | `entries/:id` | 删除记录并把原图入私有对象删除队列 |
| POST | `entries/:id/recognize` | 读私有原图、生成识别副本调用视觉模型，严格校验 JSON 后写 `meta.ai` |
| POST | `digest` | 生成或重新生成某日小结 |
| GET | `digest?date=` | 读取某日小结 |
| GET | `images/:imageId` | 成员校验后经私有媒体管线返回原图，支持 Range、`no-store` |

约束：上传单图 1 字节–25 MB，仅接受魔数校验通过的 JPEG/PNG/GIF/WebP；GIF 仅取首帧识别、原图保留；
服务端再次解码确认尺寸（最短边 ≥16px）。暂存图片归属「空间 + 账号」，其他成员和其他空间无法盗用；
暂存超过 1 小时未建记录的图片由认证流量驱动的清理钩子回收并删除对象，无常驻轮询。

## 持久化、迁移与回退

新增四张表，均为 `CREATE TABLE IF NOT EXISTS`，SQLite 与 PostgreSQL 同脚本兼容，启动时幂等建表：

- `daily_entries`：记录主体（分区、自然日、标题、摘要、附言、状态、`meta` JSON、创建人、时间）。
- `daily_images`：记录图片（复用 `uploads` 私有对象命名空间与删除队列，存尺寸和排序）。
- `daily_uploads`：两阶段上传的暂存元数据（含宽高，1 小时 TTL）。
- `daily_digests`：按「空间 + 日期」的每日小结。

**升级**：只新增表，不 ALTER 任何现有表；`storage_jobs.usage()` 的统计表白名单加入 `daily_images`，
数据库卷、媒体目录与证书卷不变。图片对象复用 `uploads` 命名空间，因此不需要修改 `storage_jobs` 的 namespace
CHECK 约束，预留、发布、配额、删除队列逻辑零改动。

**回退**：旧版本镜像忽略新表即可正常运行，新表占用空间但不影响待办、笔记、媒体、密码箱与晚安故事；
如需彻底清理，先让删除队列清完对象，再按 `daily_images`、`daily_uploads`、`daily_entries`、`daily_digests`
的顺序手动 DROP（外键级联也可）。回退版本的 `storage_jobs.usage()` 不引用 `daily_images`，无副作用。

## 限流、隐私与故障降级

- 每账号限流：图片上传 60 次/小时（在读入大报文前拦截）；识别 30 次/小时、60 次/日；每日小结 20 次/日；视觉调用独立最多 2 并发，与晚安故事的并发槽分开。
- 暂存中的图片（`daily_uploads`，最长 1 小时 TTL）同样计入空间与总存储配额，配额检查对重复暂存持续有效；暂存对象被 `storage_jobs.linked()` 引用保护，慢上传不会被清扫误删。
- Pillow 启用时模块级设置 `MAX_IMAGE_PIXELS = 6400 万`，把解压炸弹警告提升为错误，在读取像素前以 400 拒绝超大尺寸图片；Pillow 缺失时仍走原有「缺少图片处理组件」降级。
- 只把识别副本和附言发往固定百炼端点，不发送姓名、账号或其他笔记；模型不接收可公开访问的图片 URL，
  图片始终经私有存储在服务端读取，浏览器拿到的原图接口也带成员鉴权与 `no-store`。
- 供应商错误只记录固定枚举（认证、限流、模型权限、不可用、网络超时、响应无效、图片处理、未知）与 HTTP 状态码段，
  错误响应和日志不含密钥、签名 URL、请求体或供应商原始报文。
- 图片处理组件（Pillow）在函数内延迟导入，缺失时识别返回明确 503，不影响服务启动与记录功能；
  模型返回畸形 JSON、缺字段或超限时判定失败并允许重试，不写入半成品结果。
- 浏览器不缓存私密 API 与原图；退出登录或撤销空间权限后，前端清掉本地对象 URL 与今日记录状态。
